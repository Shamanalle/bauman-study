# Руководство по участию в разработке (Contributing Guide)

Спасибо за интерес к развитию проекта **bauman-study**! Этот проект создан студентами для студентов, чтобы облегчить подготовку к экзаменам, рубежным контролям (РК), зачётам и контрольным работам (КР) в МГТУ им. Н.Э. Баумана.

---

## 🧭 Архитектура проекта

Проект построен как легковесное SPA-приложение на чистом JavaScript (ES Modules) с поддержкой PWA и возможностью полной компиляции в автономные офлайн-HTML файлы:

```
src/
├── css/             # Модульные стили (base, layout, cards, practice, flashcard, dark, responsive)
├── js/              # Логика платформы (app, practice-browser, flashcard, sr-engine, exam-simulator)
├── data/            # JSON-бандлы по предметам и видам контроля
└── public/          # Статические ресурсы (иконки, manifest.json, sw.js)
scripts/             # Скрипты валидации и сборки автономных бандлов
bundles/             # Сгенерированные автономные HTML-файлы
```

## 🛠 Быстрый старт

### Требования
- **Node.js** v18+ или v20+
- **npm** v9+

### Установка и запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/Shamanalle/bauman-study.git
   cd bauman-study
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Запустите dev-сервер:
   ```bash
   npm run dev
   ```
4. Откройте в браузере: `http://localhost:5173/`

## 📋 Структура учебных материалов (`src/data/`)

Каждое контрольное мероприятие хранится в отдельной папке: `src/data/<subject>/<assessment>/`:
- `meta.json` — метаданные раздела (заголовок, иконка, цвет, флаги режима).
- `index.json` — список секций.
- `section-*.json` — файлы секций с вопросами или задачами.

### 1. Теоретические карточки (Theory Mode)
Карточка вопроса строится по 5-блочной структуре:
- `formalText` / `statement` — строгое математическое определение или формулировка теоремы.
- `formula` — ключевая формула (рендерится в `$$...$$`).
- `insight` — объяснение простыми словами («на пальцах»).
- `note` / `examSay` — важные замечания для ответа на экзамене.
- `proof` / `steps` — доказательство или вывод с пошаговыми блоками.
- `example` — прикладной пример применения.

### 2. Практические бандлы (Practice Mode)
Практический бандл содержит:
- **Формулы и методы решения**: блоки с теорией, алгоритмом и примерами.
- **Банк задач**: формулировки, подсказки, пошаговые решения (`steps: [{ title, text, math }]`).
- **Билеты контрольных / экзаменов**: наборы типовых задач для симулятора экзамена с таймером.

## 📐 Правила оформления математических формул (KaTeX)

1. **Инлайн-формулы**: используйте одиночные доллары `$x^2 + y^2 = R^2$` или `\( ... \)`.
2. **Выключные формулы (Display math)**: используйте двойные доллары:
   ```markdown
   $$\int_{a}^{b} f(x)\,dx = F(b) - F(a)$$
   ```
3. **Кириллица в формулах**: всегда оборачивайте русский текст в `\text{...}`:
   ```markdown
   $$\vec{F}_{\text{тр}} = \mu N$$
   ```
4. **Матрицы и системы уравнений**:
   ```markdown
   $$\begin{pmatrix} a & b \\ c & d \end{pmatrix}$$
   ```

## 🧪 Валидация и тестирование

Перед созданием Pull Request обязательно запустите локальные проверки:

```bash
# 1. Валидация всех 17 практических бандлов
npm run validate:practice

# 2. Сборка продакшен-бандла Vite
npm run build

# 3. Сборка 28 автономных офлайн HTML-бандлов
npm run bundle

# 4. Сборка единого файла платформы
npm run build:platform
```

Все проверки должны завершиться с кодом `0` и без ошибок.

## 🌿 Процесс создания Pull Request

1. Создайте ветку для ваших изменений:
   ```bash
   git checkout -b feature/topic-or-fix-name
   ```
2. Делайте атомарные, понятные коммиты в соответствии с [Conventional Commits](https://www.conventionalcommits.org/):
   - `feat: добавить практический бандл по термодинамике`
   - `fix: исправить формулу в билете 3 по линейной алгебре`
   - `docs: обновить руководство по запуску`
3. Отправьте ветку на GitHub и откройте **Pull Request** в ветку `master`.
4. Дождитесь успешного прохождения автоматических тестов (GitHub Actions CI).
