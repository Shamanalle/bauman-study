# Theory Bundle Generator

Генерация JSON-данных теоретических контрольных мероприятий для платформы `bauman-study`.
Теоретический бандл — это **самодостаточный инструмент для подготовки к теоретической части** РК/экзамена/зачёта.

> ### 🎯 Контекст миссии
>
> Ты создаёшь **учебные карточки, по которым реальные студенты МГТУ им. Баумана будут готовиться к экзаменам**.
> Каждую карточку студент будет читать, пытаясь запомнить определение или понять доказательство.
> Если определение неточное, доказательство неполное, или объяснение бесполезно — студент 
> не поймёт и провалит вопрос на экзамене. Это реальные последствия для реальных людей.
>
> **Твоя роль:** ты — опытный преподаватель, который пишет идеальный конспект для своих студентов.
> Каждая карточка — самодостаточная единица: студент должен полностью понять тему 
> только по ней, без дополнительных источников.
>
> **Признак хорошей работы:** студент, прочитав карточку, может пересказать определение/теорему 
> своими словами, записать формулы и воспроизвести доказательство на бумаге.

## 1. Когда использовать этот скилл

- Создание/обновление **теоретического** бандла для РК (рубежный контроль)
- Создание/обновление **теоретической части** экзамена (без задач!)
- Создание/обновление бандла зачёта
- Любая работа с вопросами типа: определения, теоремы, формулировки, доказательства

> **НЕ** используй для практических задач (КР, задачи экзамена) — для этого есть `practice-bundle-gen`.

## 2. Откуда брать контент: папка `new_sources/`

Все первоисточники лежат в **`new_sources/`** в корне проекта:

```
new_sources/
├── <Предмет>/
│   ├── Контрольное Мероприятие/
│   │   ├── <Код> - РК - N - Вопросы.txt   ← ГЛАВНЫЙ источник: список вопросов РК
│   │   ├── <Код> - РК - N.txt             ← ответы на вопросы РК
│   │   └── ...
│   ├── Сессия/
│   │   ├── <Код> - Сессия - Вопросы.txt   ← список вопросов экзамена
│   │   ├── <Код> - Сессия - Билеты.txt    ← варианты билетов
│   │   └── <Код> - Сессия.txt             ← ответы
│   ├── Зачет/
│   │   └── <Код> - Теория к зачету.txt
│   ├── Домашнее Задание/
│   └── Лекции/                            ← теоретическая база
│       ├── <Код> - Лекция 1.txt
│       └── ...
```

Коды предметов:

| Предмет | Код |
| --- | --- |
| Дифференциальные Уравнения | ИиДУ |
| Линейная Алгебра | ЛА |
| Физика | Физ |
| Алгоритмические Языки | АЯ |

### Приоритет источников

| Приоритет | Источник | Что берём |
| --- | --- | --- |
| 🥇 1 | `РК - N - Вопросы.txt` / `Сессия - Вопросы.txt` | Точный список вопросов → скелет бандла |
| 🥇 1 | `РК - N.txt` / `Сессия.txt` | Ответы → formalText, steps |
| 🥈 2 | `src/data/<subject>/textbook/ch-NN-*.json` | Расширенные объяснения, примеры, визуалы |
| 🥈 2 | `Лекции/<Код> - Лекция N.txt` | Формулировки, доказательства, формулы |
| 🥉 3 | `Литература/` | Дополнительный справочный материал |

### Алгоритм работы с источниками

**Шаг 1.** Прочитай файл вопросов — каждый пронумерованный вопрос → одна карточка.
**Шаг 2.** Прочитай файл ответов → заполни `formalText` и `steps`.
**Шаг 3.** Прочитай textbook → добавь `insight`, `example`.
**Шаг 4.** Прочитай лекции → уточни формулировки и доказательства.

> **КРИТИЧЕСКИ ВАЖНО:**
> - `title` вопроса берётся **в точной формулировке** из файла вопросов
> - `formalText` определений копируется **дословно** из ответов (переводится в KaTeX)
> - Если `.txt` файл не найден — спроси пользователя, откуда брать вопросы

```json
{

}
```

## 4. Структура карточки — «5 блоков»

Каждая карточка отображается студенту как последовательность визуально различных блоков с лейблами.
Студент должен моментально понимать, где определение (которое он пишет на РК), где пояснение,
а где доказательство. Никакого «потока текста без подписей».

### Порядок отображения карточки

```
① Формула          (formula)    — если есть. Главная формула крупно в рамке.
② 📖 Определение   (formalText) — всегда. Полный формальный текст.
③ 💡 Простыми словами (insight) — всегда. Одно поле: аналогия + ключевая мысль.
④ 📌 Уточнение     (note)      — опционально. Дополнительные связи, нюансы, советы.
⑤ 📐 Вывод/📝 Пример           — опционально, раскрываемые блоки.
```

### 4.1 Обязательные поля

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `number` | Уникальный числовой ID внутри секции (1, 2, 3... **последовательно!**) |
| `title` | `string` | Точное название вопроса из файла-источника (2-10 слов) |
| `type` | `string` | Один из: `"Определение"`, `"Теорема"`, `"Формулировка"`, `"Закон"`, `"Понятие"`, `"Формула + вывод"` |
| `formalText` | `string` | **Полный** текст определения/теоремы — то, что студент **пишет на контрольной** |
| `insight` | `string` | Объяснение «простыми словами»: аналогия + ключевая мысль. Разговорный стиль |

### 4.2 Условно-обязательные поля

| Поле | Когда обязательно | Описание |
| --- | --- | --- |
| `formula` | Если есть формулы | Главная формула карточки (KaTeX, **БЕЗ** `$$`) |
| `steps` | Теоремы, формулы с выводом | Пошаговое доказательство/вывод (массив объектов) |
| `example` | Теоремы + Формулы | Конкретный числовой пример: `{"title": "📝", "text": "..."}` |
| `conditions` | Если есть условия | Массив строк: условия применимости |
| `proofTitle` | Если нужен нестандартный лейбл | Заголовок раскрывашки (вместо «Доказательство» / «Вывод») |

### 4.3 Опциональные поля

| Поле | Описание |
| --- | --- |
| `note` | Уточнение: нюанс, частая ошибка, связь с другой темой, совет для экзамена |
| `visual` | SVG-ссылка: `"svg:img_1"` → `src/data/<subject>/svg/img_1.svg` |
| `visualLabel` | Подпись к визуализации |

### 4.4 ID типов — строгий список

Тип `type` должен быть **ровно одним** из этого списка:
- `"Определение"` — формальное определение понятия
- `"Теорема"` — теорема с доказательством (steps обязательны)
- `"Формулировка"` — формулировка закона/принципа без доказательства
- `"Закон"` — физический/математический закон
- `"Понятие"` — для IT-предметов (конструкции языка, паттерны)
- `"Формула + вывод"` — формула с обязательным выводом (steps обязательны)

Не используй гибридные типы вроде `"Определение + теорема"` или `"Теорема + доказательство"`.
Если вопрос содержит и определение, и теорему — выбери основной тип по тому, что спрашивают на экзамене.

## 5. Правила контента

### 5.1 Правила для `formalText`

Это **ядро карточки** — то, что студент будет писать на контрольной. Оно отображается с лейблом «📖 Определение / Формулировка / Теорема».

1. **Определения:** Полный строгий текст. Выделяй определяемый термин жирным: `**первообразной**`
2. **Теоремы:** Полная формулировка БЕЗ доказательства (оно в `steps`)
3. **Законы:** Формулировка + физический смысл
4. Используй KaTeX: `$...$` инлайн, `$$...$$` блок
5. Нумерованные условия/аксиомы — через `\\n1. ... \\n2. ...`
6. **Никаких Unicode-символов** для математики (∫, √, α, ²) — только KaTeX

### 5.2 Правила для `insight` (объединяет бывшие tldr + intuition + keyIdea)

Одно поле вместо трёх. Студент видит его с лейблом «💡 Простыми словами». Цель: помочь понять и запомнить.

Хороший insight содержит:
- **Аналогию** из реальной жизни или смежной области
- **Ключевую мысль** — что самое важное в этой карточке

Пиши разговорным языком, как если объясняешь другу. 2-4 предложения.

| ❌ Плохо | ✅ Хорошо |
| --- | --- |
| `"Это важное определение"` | `"Первообразная — это спидометр наоборот: знаешь скорость → восстанавливаешь путь. Ключевое: операция, обратная дифференцированию."` |
| `"Применяется в физике"` | `"Как лифт: неважно каким путём ехал, работа зависит только от разницы этажей. Потенциальное поле — никаких вихрей."` |

### 5.3 Правила для `formula`

- Чистый KaTeX **БЕЗ** `$$...$$` (рендерер сам оборачивает)
- Только главная формула карточки

```json
"formula": "F'(x) = f(x)"          // ✅
"formula": "$$F'(x) = f(x)$$"      // ❌ дважды обернёт в $$
```

### 5.4 Правила для `note`

Опциональное уточнение. Отображается с лейблом «📌». Сюда идёт:
- Связь с другими вопросами/темами
- Частая ошибка на экзамене
- Конкретный совет что сказать/написать
- Нюанс, который не вошёл в formalText

Если нечего уточнять — не добавляй поле. Оно **опционально**.

### 5.5 Правила для `steps`

1. **Минимум 3 шага** для каждого доказательства/вывода
2. Каждый шаг — логически завершённый этап
3. `title` шагов — действия: «Запишем...», «Подставим...», «Получим...»
4. Все `title` **уникальны** в пределах карточки
5. Формулы — в `math` поле каждого шага
6. `tip` — предупреждения и частые ошибки
7. **Не пиши «очевидно»** — разжуй каждый переход

Формат:

```json
"steps": [
  {
    "title": "Запишем определение",
    "text": "По определению, $F'(x) = f(x)$, значит...",
    "math": "$$F(x) = \\\\int f(x)\\\\,dx$$",
    "tip": "Не забудь проверить граничные условия!"
  }
]
```

### 5.6 Правила для `example`

- Конкретный числовой пример с вычислениями
- Формат: `{"title": "📝 Пример", "text": "...", "math": "$$...$$"}`

### 5.7 Форматирование текста

| Правило | ✅ Правильно | ❌ Неправильно |
| --- | --- | --- |
| Жирный текст | `**Базис**` | `<strong>Базис</strong>` |
| Курсив | `*курсив*` | `<em>курсив</em>` |
| Перенос строки | `\\n` (в JSON: `\\\\n`) | `<br>` |
| Инлайн-формулы | `$F'(x) = f(x)$` | `F'(x) = f(x)` |
| Блочные формулы | `$$\\\\int f(x)\\,dx$$` | `$\\int f(x)\\,dx$` |
| Экранирование в JSON | `\\\\int`, `\\\\frac` | `\int`, `\frac` |

> **НИКОГДА** не используй HTML-теги (`<strong>`, `<em>`, `<br>`, `<ol>`, `<li>`) в текстовых полях.
> Функция `nl()` в `text-utils.js` автоматически конвертирует markdown → HTML.

## 6. Эталоны карточек

### 6.1 Эталон: Определение

```json
{
  "id": 1,
  "title": "Определение первообразной",
  "type": "Определение",
  "formalText": "Пусть функции $F(x)$ и $f(x)$ заданы на одном и том же промежутке $X$.\\n\\nФункция $F(x)$ называется **первообразной** для $f(x)$ на этом промежутке, если для любого $x \\\\in X$ существует производная $F'(x)$, равная $f(x)$:\\n\\n$$F'(x) = f(x), \\\\quad \\\\forall\\\\, x \\\\in X$$\\n\\nДля граничной точки (если она принадлежит $X$) под $F'(x)$ понимается соответствующая односторонняя производная.",
  "formula": "F'(x) = f(x)",
  "insight": "Первообразная — это спидометр наоборот: знаешь скорость v(t) → восстанавливаешь путь S(t), потому что S'(t) = v(t). Определена с точностью до константы: если F — первообразная, то F + C тоже.",
  "example": {
    "title": "📝 Пример",
    "text": "$F(x) = \\\\frac{x^3}{3}$ — первообразная для $f(x) = x^2$, т.к. $\\\\left(\\\\frac{x^3}{3}\\\\right)' = x^2$.\\n\\nНо и $G(x) = \\\\frac{x^3}{3} + 7$ тоже первообразная — производная та же."
  },
  "note": "На РК обязательно указать «для любого $x \\\\in X$» и что $F'(x) = f(x)$. Не забудь про одностороннюю производную на границе."
}
```

**Что делает его хорошим:**
- `formalText` — полный, с KaTeX, с выделением термина **жирным**
- `insight` — аналогия (скорость→путь) + ключевая мысль (с точностью до C), 2 предложения
- `formula` — без `$$`, чистый KaTeX
- `note` — конкретный совет для РК
- Нет HTML-тегов, только markdown

## 7. Стратегии по типам предметов

### 7.1 Точные науки (Физика, ИиДУ, ЛинАлг)

- `formalText` — строгие математические формулировки с KaTeX
- `steps` — полные доказательства с промежуточными выкладками
- `formula` — ключевая формула крупно
- `conditions` — условия применимости
- `visual` — SVG-диаграмма для ключевых концепций
- `insight` — физические/геометрические аналогии

### 7.2 IT-предметы (АЯ C++, ТиМП)

- Код в `<pre class="code-block"><code class="language-cpp">...</code></pre>`
- `insight` — аналогия из жизни + когда и зачем использовать
- `example` — работающий пример кода с комментариями

### 7.3 Дискретная математика (МОИ)

- Таблицы истинности в HTML-таблицах внутри `formalText`
- `visual` — SVG для контактных схем, диаграмм Хассе
- Формулы в KaTeX: `$\\oplus$`, `$\\|\\mathbf{a}\\|$`

## 8. Алгоритм генерации (пошагово)

> LLM при большом объёме работы склонны к деградации качества —
> сокращают карточки, пропускают insight, пишут формальные заглушки. Поэтому процесс включает
> обязательные промежуточные проверки после каждого батча.

### Шаг 1: Планирование

1. Прочитай файл вопросов → определи количество карточек
2. Определи секции (тематические блоки)
3. Определи типы карточек (Определение/Теорема/...)
4. Подготовь источники: ответы, textbook, лекции

### Шаг 2: Генерация секций (БАТЧАМИ)

> **ПРАВИЛО БАТЧЕЙ:** Генерируй карточки батчами по **10 штук**.
> После каждого батча — обязательная проверка (чеклист ниже).
> Не генерируй >10 карточек без промежуточной валидации.

### Шаг 3: Промежуточная проверка после батча

Для каждой карточки в батче:
```
✅ Есть formalText? (полный формальный текст)
✅ Есть insight? (непустой, аналогия + ключевая мысль)
✅ type — из списка разрешённых?
✅ Для Теорем / Формула + вывод: есть steps с ≥3 шагами?
✅ Для Теорем / Формул: есть example?
✅ Нет HTML-тегов (<strong>, <em>) в formalText, insight, note?
✅ ID последовательные?
```

Перечитай 3 случайных карточки из батча — insight действительно помогает понять?

### Шаг 4: Автоматическая валидация

После генерации ВСЕХ секций:

```bash
cp .agent/skills/theory-bundle-gen/scripts/validate-theory.js /tmp/validate-theory.js
node /tmp/validate-theory.js src/data/<subject>/<assessment>/
```

Цикл: генерация → валидация → исправление → валидация → ... **пока 0 ошибок**.

### Шаг 5: Сборка и финальный контроль

```bash
npm run build && npm run bundle && node scripts/build-platform.js
```

## 11. Покрытие вопросов

> Каждый вопрос из файла-источника должен быть представлен в бандле.
> Если в источнике 30 вопросов — в бандле должно быть 30 карточек.
> Никаких пропусков или объединений вопросов без явного одобрения пользователя.

После генерации выведи таблицу покрытия:

```
Источник: <файл вопросов>
Всего вопросов: 30
Покрыто карточек: 30

Секция 1 (Механика): 12 вопросов ✅
```
