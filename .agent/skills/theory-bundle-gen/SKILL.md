# Theory Bundle Generator

Генерация JSON-данных теоретических контрольных мероприятий для платформы `bauman-study`.

---

## 1. Когда использовать этот скилл

- Создание/обновление **теоретического** бандла для РК (рубежный контроль)
- Создание/обновление **теоретической части** экзамена (без задач!)
- Создание/обновление бандла зачёта
- Любая работа с вопросами типа: определения, теоремы, формулировки, доказательства

> **НЕ** используй для практических задач (КР, задачи экзамена) — для этого есть `practice-bundle-gen`.

---

## 2. Структура выходных файлов

Для каждого бандла в `src/data/<subject>/<assessment>/` создаются:

```
src/data/<subject>/<assessment>/
├── meta.json                              # Метаданные
├── index.json                             # Список секций
├── section-01-<имя-секции>.json           # Секция 1
├── section-02-<имя-секции>.json           # Секция 2
└── ...
```

### meta.json
```json
{
  "title": "Физика",
  "subtitle": "РК-1 · Механика и колебания",
  "icon": "⚛️",
  "shortCode": "phyrk1",
  "bundleName": "Физика_РК-1"
}
```
> Поле `"practiceMode": true` НЕ добавляется — это теоретический бандл.

### index.json
```json
{
  "sections": [
    "section-01-механика.json",
    "section-02-колебания.json"
  ]
}
```

### section-NN-<имя>.json
```json
{
  "section": "Механика",
  "icon": "⚙️",
  "questions": [ /* массив вопросов */ ]
}
```

## 3. Схема вопроса (карточки)

### 3.1 Обязательные поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `number` | Уникальный числовой ID внутри секции (1, 2, 3...) |
| `title` | `string` | Краткое название вопроса (2-8 слов) |
| `type` | `string` | Тип: `"Определение"`, `"Теорема"`, `"Формулировка"`, `"Закон"`, `"Понятие"` |
| `formalText` | `string` | **Полный** текст определения/теоремы/закона. Главное содержание карточки. KaTeX: `$$...$$` для блоков, `$...$` для инлайн |

### 3.2 Рекомендуемые поля

| Поле | Тип | Описание |
|------|-----|----------|
| `tldr` | `string` | Суть вопроса 1-2 предложениями. "Если бы это объяснял другу" |
| `intuition` | `string` | Аналогия или интуитивное объяснение. Стиль: *курсив*, разговорный |
| `keyIdea` | `string` | Ключевая идея (для быстрого повторения перед контрольной) |
| `formula` | `string` | Главная формула (KaTeX, без `$$`). Рендерится в отдельном блоке |
| `steps` | `array` | Шаги доказательства/вывода (для теорем 3 балла и выше) |
| `proof` | `string` | Альтернатива `steps` — сплошной текст доказательства |
| `proofTitle` | `string` | Заголовок блока доказательства (по-умолч.: "Доказательство") |
| `conditions` | `array<string>` | Условия применимости (рендерятся как маркированный список) |
| `example` | `object` | Пример: `{"title": "📝 Пример", "text": "...", "math": "..."}` |
| `examSay` | `string` | Совет для экзамена/РК — "что сказать на контрольной" |
| `note` | `string` | Дополнительная заметка (связи с другими вопросами, нюансы) |
| `visual` | `string` | SVG-ссылка: `"svg:img_1"` (файл `src/data/<subject>/svg/img_1.svg`) |
| `visualLabel` | `string` | Подпись к визуализации |
| `advanced` | `string` | Строгая формулировка (дополнительный блок для продвинутых) |
| `advancedProof` | `string` | Строгое доказательство в advanced-блоке |

### 3.3 Формат поля `steps`

```json
"steps": [
  {
    "title": "Шаг 1: Запишем определение",
    "text": "По определению, $F'(x) = f(x)$, значит...",
    "math": "$$F(x) = \\int f(x)\\,dx$$",
    "tip": "Не забудь проверить граничные условия!"
  },
  {
    "title": "Шаг 2: Применим формулу Ньютона-Лейбница",
    "text": "..."
  }
]
```

Каждый шаг содержит:
- `title` — название шага (обязательно)
- `text` — содержание (обязательно)
- `math` — формула в KaTeX (опционально)
- `tip` — подсказка/предупреждение (опционально, рендерится жёлтой плашкой)

Альтернативно `steps` могут быть строками:
```json
"steps": [
  "**Шаг 1**: Запишем определение...",
  "**Шаг 2**: Подставим..."
]
```

## 4. Алгоритм генерации бандла

### Шаг 1: Определить источники

Для каждого бандла нужны:

1. **Файл вопросов** (ПРИОРИТЕТ №1):
   - `new_sources/<предмет>/Контрольное Мероприятие/<Код> - РК - N - Вопросы.txt`
   - или `new_sources/<предмет>/Сессия/<Код> - Сессия - Вопросы.txt`
   - или `new_sources/<предмет>/Зачет/<Код> - Теория к зачету.txt`

2. **Файл ответов**:
   - `new_sources/<предмет>/Контрольное Мероприятие/<Код> - РК - N.txt`
   - или `new_sources/<предмет>/Сессия/<Код> - Сессия.txt`

3. **Учебное пособие (textbook)** — расширенный контент:
   - `src/data/<subject>/textbook/ch-NN-<name>.json`

4. **Лекции** — дополнительный контент:
   - `new_sources/<предмет>/Лекции/<Код> - Лекция N.txt`

5. **Литература** — справочный материал:
   - `new_sources/<предмет>/Литература/`

### Шаг 2: Читай файл вопросов → скелет бандла

Прочитай файл вопросов. Каждый пронумерованный вопрос → одна карточка.

> **КРИТИЧЕСКИ ВАЖНО**: Формулировка вопроса (поле `title`) берётся **в точной формулировке** из файла вопросов.
> Допускается только незначительное сокращение для title — полная формулировка идёт в `formalText`.

#### Типы вопросов (определяются по баллам/контексту):
- **1 балл** → `type: "Определение"` — краткое определение
- **3 балла** → `type: "Теорема"` — теорема с доказательством → НУЖНЫ `steps`!
- без баллов → определяй по контексту: `"Закон"`, `"Понятие"`, `"Формулировка"`

#### Группировка в секции:
Вопросы группируются по тематическим блокам из файла вопросов:
- «Физические основы механики» → секция «Механика»
- «Теория колебаний» → секция «Колебания»
- и т.д.

### Шаг 3: Наполни содержание каждого вопроса

Для каждого вопроса из скелета:

1. Найди соответствующий ответ в **файле ответов** → `formalText` (основное содержание)
2. Найди расширенное объяснение в **textbook** → улучши `formalText`, добавь `intuition`, `example`
3. Найди альтернативные объяснения в **лекциях** → добавь `note`, `examSay`
4. Для теорем (3 балла) — **обязательно** добавь полное доказательство в `steps`

#### Правила наполнения `formalText`:

1. **Определения**: Полный текст определения в строгой математической формулировке
2. **Теоремы**: Полная формулировка теоремы (без доказательства — оно в steps)
3. **Законы**: Формулировка + физический смысл
4. **Используй KaTeX** для всех формул: `$...$` инлайн, `$$...$$` блок

#### Правила наполнения `steps` (доказательства):

1. Каждый шаг — логически завершённый этап доказательства
2. Названия шагов — действия: «Запишем...», «Подставим...», «Получим...»
3. Формулы — в `math` поле каждого шага
4. Предупреждения — в `tip`
5. **Не пиши «очевидно»** — разжуй каждый переход

#### Правила наполнения `tldr`:

- Пиши как будто объясняешь однокурснику в 1-2 предложениях
- Акцент на суть, а не на формальности
- Пример: *«Первообразная — это функция, производная которой даёт исходную. F'(x) = f(x).»*

#### Правила наполнения `intuition`:

- Аналогия из реальной жизни или смежных областей
- Стиль разговорный, с эмоджи
- Пример: *«Представь, что интеграл — это спидометр наоборот: если ты знаешь скорость (f), интеграл даст тебе пройденный путь (F).»*

### Шаг 4: Сгруппируй, запиши JSON-файлы

1. Раздели вопросы по секциям (из файла вопросов)
2. Каждая секция → `section-NN-<slug>.json`
3. Подбери иконки для секций (🔧⚙️📐🎵🌊🔬💡⚡)
4. Запиши `meta.json` и `index.json`

### Шаг 5: Валидация

После записи файлов:

1. **Проверь JSON** — валидный синтаксис
2. **Проверь KaTeX** — все формулы должны ренд ериться
3. **Проверь покрытие** — каждый вопрос из файла вопросов должен быть в бандле
4. **Открой в браузере**: `http://localhost:5173/?subject=<subject>&assessment=<assessment>`

## 5. Стратегии по типам предметов

### 5.1 Точные науки (Физика, ИиДУ, ЛинАлг)

- `formalText` — строгие математические формулировки с KaTeX
- `steps` — полные доказательства с промежуточными выкладками
- `formula` — ключевая формула крупно
- `conditions` — условия применимости
- `visual` — SVG-диаграмма для ключевых концепций

### 5.2 IT-предметы (АЯ C++)

- `formalText` — определения + примеры кода
- Код оборачивай в: `<pre class="code-block"><code class="language-cpp">...</code></pre>`
- `example` — работающий пример кода
- `keyIdea` — когда и зачем использовать эту конструкцию

### 5.3 Дискретная математика (МОИ)

- `formalText` — определения из дискретной математики
- Таблицы истинности в формате HTML-таблиц внутри formalText
- `visual` — SVG для контактных схем, диаграмм

## 7. Чеклист качества

Перед завершением убедись:

- [ ] Все вопросы из файла-источника присутствуют в бандле
- [ ] Формулировки `title` точно соответствуют источнику
- [ ] Все формулы в `formalText` и `formula` проверены
- [ ] Теоремы (3 балла) имеют `steps` с полным доказательством
- [ ] `tldr` и `intuition` написаны понятным языком
- [ ] JSON-файлы валидны (нет незакрытых скобок, битых кавычек)
- [ ] `meta.json`, `index.json` существуют и корректны
- [ ] Нет неиспользуемых ссылок на SVG (`visual` → файл существует)
