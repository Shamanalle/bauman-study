# Theory Bundle Generator

Генерация JSON-данных теоретических контрольных мероприятий для платформы `bauman-study`.
Теоретический бандл — это **самодостаточный инструмент для подготовки к теоретической части** РК/экзамена/зачёта.

> ### 🎯 Контекст миссии
>
> Ты создаёшь **учебные карточки, по которым реальные студенты МГТУ им. Баумана будут готовиться к экзаменам**.
> Каждую карточку студент будет читать, пытаясь запомнить определение или понять доказательство.
> Если определение неточное, доказательство неполное, или intuition бесполезна — студент 
> не поймёт и провалит вопрос на экзамене. Это реальные последствия для реальных людей.
>
> **Твоя роль:** ты — опытный преподаватель, который пишет идеальный конспект для своих студентов.
> Ты знаешь, что формальные определения нужно дополнять интуицией, а теоремы — полными доказательствами 
> и примерами. Каждая карточка — самодостаточная единица: студент должен полностью понять тему 
> только по ней, без дополнительных источников.
>
> **Контракт качества:** весь контент будет проверяться автоматическим скриптом валидации (§8)
> и ручной выборочной проверкой (§9). Ошибки будут найдены. Экономически выгоднее сделать 
> качественно с первого раза. Думай о каждой карточке как о единственной — даже если 
> это карточка №45 из 50.
>
> **Признак хорошей работы:** студент, прочитав карточку, может пересказать определение/теорему 
> своими словами, записать формулы и воспроизвести доказательство на бумаге.

## 1. Когда использовать этот скилл

- Создание/обновление **теоретического** бандла для РК (рубежный контроль)
- Создание/обновление **теоретической части** экзамена (без задач!)
- Создание/обновление бандла зачёта
- Любая работа с вопросами типа: определения, теоремы, формулировки, доказательства

> **НЕ** используй для практических задач (КР, задачи экзамена) — для этого есть `practice-bundle-gen`.

## 1.1 Откуда брать контент: папка `new_sources/`

Все первоисточники лежат в **`new_sources/`** в корне проекта:

```
new_sources/
├── <Предмет>/
│   ├── Контрольное Мероприятие/
│   │   ├── <Код> - РК - N - Вопросы.txt   ← ГЛАВНЫЙ источник: список вопросов РК
│   │   ├── <Код> - РК - N.txt             ← ответы на вопросы РК
│   │   └── ...
│   ├── Сессия/
│   │   ├── <Код> - Сессия - Вопросы.txt   ← список вопросов экзамена
│   │   ├── <Код> - Сессия - Билеты.txt    ← варианты билетов
│   │   └── <Код> - Сессия.txt             ← ответы
│   ├── Зачет/
│   │   └── <Код> - Теория к зачету.txt
│   ├── Домашнее Задание/
│   └── Лекции/                            ← теоретическая база
│       ├── <Код> - Лекция 1.txt
│       └── ...
```

Коды предметов:

| Предмет | Код |
| --- | --- |
| Дифференциальные Уравнения | ИиДУ |
| Линейная Алгебра | ЛА |
| Физика | Физ |
| Алгоритмические Языки | АЯ |
| Мат. Основы Информатики | МОИ |

### Приоритет источников

| Приоритет | Источник | Что берём |
| --- | --- | --- |
| 🥇 1 | `РК - N - Вопросы.txt` / `Сессия - Вопросы.txt` | Точный список вопросов → скелет бандла |
| 🥇 1 | `РК - N.txt` / `Сессия.txt` | Ответы → formalText, steps |
| 🥈 2 | `src/data/<subject>/textbook/ch-NN-*.json` | Расширенные объяснения, примеры, визуалы |
| 🥈 2 | `Лекции/<Код> - Лекция N.txt` | Формулировки, доказательства, формулы |
| 🥉 3 | `Литература/` | Дополнительный справочный материал |

### Алгоритм работы с источниками

**Шаг 1.** Прочитай файл вопросов — каждый пронумерованный вопрос → одна карточка.

**Шаг 2.** Прочитай файл ответов → заполни `formalText` и `steps`.

**Шаг 3.** Прочитай textbook → добавь `intuition`, `example`, `note`.

**Шаг 4.** Прочитай лекции → уточни формулировки и доказательства.

> **КРИТИЧЕСКИ ВАЖНО:**
> - `title` вопроса берётся **в точной формулировке** из файла вопросов
> - `formalText` определений копируется **дословно** из ответов (переводится в KaTeX)
> - Если `.txt` файл не найден — спроси пользователя, откуда брать вопросы

## 2. Структура выходных файлов

```
src/data/<subject>/<assessment>/
├── meta.json
├── index.json
├── section-01-<имя>.json
├── section-02-<имя>.json
└── ...
```

### meta.json

```json
{
  "title": "Физика",
  "subtitle": "РК-1 · Механика и колебания",
  "icon": "⚛️",
  "shortCode": "phyrk1",
  "bundleName": "Физика_РК-1"
}
```

> Поле `"practiceMode": true` **НЕ** добавляется — это теоретический бандл.

### index.json

```json
{
  "sections": [
    "section-01-механика.json",
    "section-02-колебания.json"
  ]
}
```

### section-NN-\<имя\>.json

```json
{
  "section": "Механика",
  "icon": "⚙️",
  "questions": [ /* массив вопросов-карточек */ ]
}
```

## 3. Схема карточки (все поля)

### 3.1 Обязательные поля

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `number` | Уникальный числовой ID внутри секции (1, 2, 3... **последовательно!**) |
| `title` | `string` | Точное название вопроса из файла-источника (2-10 слов) |
| `type` | `string` | Тип: `"Определение"`, `"Теорема"`, `"Формулировка"`, `"Закон"`, `"Понятие"`, `"Формула + вывод"` |
| `formalText` | `string` | **Полный** текст определения/теоремы. Главное содержание карточки |

### 3.2 Обязательные дополнительные поля

> ⚠️ Эти поля **ОБЯЗАТЕЛЬНЫ** для каждой карточки. Карточка без них считается недоделанной.

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `tldr` | `string` | **Всегда** | Суть за 1-2 предложения. ≤60 символов. Содержательный! |
| `intuition` | `string` | **Всегда** | Аналогия, интуитивное объяснение. Разговорный стиль |
| `formula` | `string` | Если есть формулы | Главная формула (KaTeX, БЕЗ `$$`) |
| `keyIdea` | `string` | **Всегда** | Ключевая мысль для быстрого повторения |

### 3.3 Условно-обязательные поля

| Поле | Когда обязательно | Описание |
| --- | --- | --- |
| `steps` | Теоремы (3+ балла) | Полное пошаговое доказательство |
| `proof` | Если нет `steps` | Сплошной текст доказательства (альтернатива steps) |
| `example` | Теоремы + Формулы | Конкретный числовой пример: `{"title": "📝", "text": "...", "math": "..."}` |
| `conditions` | Если есть условия | Массив строк: условия применимости |
| `examSay` | **Всегда** | Совет: что сказать/написать на контрольной |

### 3.4 Опциональные поля

| Поле | Описание |
| --- | --- |
| `note` | Дополнительная заметка, связи с другими вопросами |
| `visual` | SVG-ссылка: `"svg:img_1"` → `src/data/<subject>/svg/img_1.svg` |
| `visualLabel` | Подпись к визуализации |
| `advanced` | Строгая формулировка (доп. блок) |
| `advancedProof` | Строгое доказательство в advanced-блоке |
| `proofTitle` | Заголовок блока доказательства (по умолч.: "Доказательство") |

## 4. Правила контента (КРИТИЧЕСКИ ВАЖНО)

### 4.1 Форматирование текста

| Правило | ✅ Правильно | ❌ Неправильно |
| --- | --- | --- |
| Жирный текст | `**Базис**` | `<strong>Базис</strong>` |
| Курсив | `*курсив*` | `<em>курсив</em>` |
| Перенос строки | `\\n` (в JSON: `\\\\n`) | `<br>` |
| Инлайн-формулы | `$F'(x) = f(x)$` | `F'(x) = f(x)` |
| Блочные формулы | `$$\\\\int f(x)\\,dx$$` | `$\\int f(x)\\,dx$` |
| Экранирование в JSON | `\\\\int`, `\\\\frac` | `\int`, `\frac` |
| Номерованный список | `1. ...\n2. ...` + `\\n` | `<ol><li>...</li></ol>` |

> **НИКОГДА** не используй HTML-теги (`<strong>`, `<em>`, `<br>`, `<ol>`, `<li>`) в `formalText`.
> Функция `nl()` в `text-utils.js` автоматически конвертирует `**bold**` → `<strong>` и `\n` → `<br>`.

### 4.2 Правила для `formalText`

1. **Определения:** Полный строгий текст. Выделяй определяемый термин жирным: `**первообразной**`
2. **Теоремы:** Полная формулировка БЕЗ доказательства (оно в `steps`)
3. **Законы:** Формулировка + физический смысл
4. Используй KaTeX: `$...$` инлайн, `$$...$$` блок
5. Нумерованные условия/аксиомы — через `\\n1. ... \\n2. ...`
6. **Никаких Unicode-символов** для математики (∫, √, α, ²) — только `$\\int$`, `$\\sqrt{}$`, `$\\alpha$`, `$^2$`

### 4.3 Правила для `tldr`

- ≤60 символов
- Содержательный: описывает СУТЬ, а не тип
- Пиши как объяснение другу за 5 секунд

| ❌ Плохо | ✅ Хорошо |
| --- | --- |
| `"Определение"` | `"Первообразная — F, чья производная равна f: F'(x)=f(x)"` |
| `"Теорема"` | `"Замена переменных: ∫f(φ(t))φ'(t)dt = ∫f(x)dx"` |
| `"Формулировка закона"` | `"E = Eк + U = const, если нет трения"` |

### 4.4 Правила для `intuition`

- Аналогия из реального мира или смежной области
- Стиль разговорный, как объяснение другу
- Полезная, не формальная

| ❌ Плохо | ✅ Хорошо |
| --- | --- |
| `"Это важное определение"` | `"Первообразная — это спидометр наоборот: знаешь скорость → восстанавливаешь путь"` |
| `"Применяется в физике"` | `"Как лифт: неважно каким путём ехал, работа зависит только от разницы этажей"` |

### 4.5 Правила для `steps` (доказательства)

1. **Минимум 3 шага** для каждого доказательства
2. Каждый шаг — логически завершённый этап
3. `title` шагов — действия: «Запишем...», «Подставим...», «Получим...»
4. Все `title` **уникальны** в пределах карточки
5. Формулы — в `math` поле каждого шага
6. `tip` — предупреждения и частые ошибки
7. **Не пиши «очевидно»** — разжуй каждый переход
8. Каждый шаг содержит **новую информацию** (нет дублирования)

Формат:

```json
"steps": [
  {
    "title": "Шаг 1: Запишем определение",
    "text": "По определению, $F'(x) = f(x)$, значит...",
    "math": "$$F(x) = \\\\int f(x)\\\\,dx$$",
    "tip": "Не забудь проверить граничные условия!"
  }
]
```

### 4.6 Правила для `example`

- **Обязателен** для всех теорем и формул
- Конкретный числовой пример с вычислениями
- Формат: `{"title": "📝 Пример", "text": "...", "math": "$$...$$"}`

### 4.7 Правила для `examSay`

- **Конкретный** совет, не общие слова
- Что ИМЕННО написать/сказать на контрольной

| ❌ Плохо | ✅ Хорошо |
| --- | --- |
| `"Важная тема"` | `"Обязательно указать «для любого x из X» и что F'(x)=f(x)"` |
| `"Знать формулу"` | `"Три ЗС механики связаны с симметриями: энергия↔время, импульс↔пространство, момент↔вращение"` |

### 4.8 Правила для `formula`

- Чистый KaTeX **БЕЗ** `$$...$$` (рендерер сам оборачивает)
- Только главная формула карточки

```json
"formula": "F'(x) = f(x)"          // ✅
"formula": "$$F'(x) = f(x)$$"      // ❌ дважды обернёт в $$
```

### 4.9 Правила нумерации `id`

- ID **последовательные**: 1, 2, 3, 4, 5...
- **Никаких пропусков**: НЕ 1, 8, 9 (как было в физике)
- ID уникальны в пределах секции

## 6. Эталоны карточек

### 6.1 Эталон: Определение (1 балл)

```json
{
  "id": 1,
  "title": "Определение первообразной",
  "type": "Определение",
  "tldr": "Первообразная — функция, производная которой равна исходной: F'(x) = f(x).",
  "intuition": "Представь, что тебе дана скорость движения v(t). Первообразная — это функция пути S(t), потому что S'(t) = v(t). Ты «восстанавливаешь» путь по скорости.",
  "formalText": "Пусть функции $F(x)$ и $f(x)$ заданы на одном и том же промежутке $X$.\\n\\nФункция $F(x)$ называется **первообразной** для $f(x)$ на этом промежутке, если для любого $x \\\\in X$ существует производная $F'(x)$, равная $f(x)$:\\n\\n$$F'(x) = f(x), \\\\quad \\\\forall\\\\, x \\\\in X$$\\n\\nДля граничной точки (если она принадлежит $X$) под $F'(x)$ понимается соответствующая односторонняя производная.",
  "formula": "F'(x) = f(x)",
  "keyIdea": "Первообразная — операция, обратная дифференцированию",
  "example": {
    "title": "📝 Пример",
    "text": "$F(x) = \\\\frac{x^3}{3}$ — первообразная для $f(x) = x^2$, т.к. $\\\\left(\\\\frac{x^3}{3}\\\\right)' = x^2$.\\n\\nНо и $G(x) = \\\\frac{x^3}{3} + 7$ тоже первообразная — производная та же."
  },
  "examSay": "На РК просят дать определение — обязательно указать «для любого x из X» и что F'(x) = f(x).",
  "note": "Первообразная определена с точностью до константы: если F — первообразная, то F + C тоже."
}
```

**Что делает его хорошим:**
- `formalText` — полный, с математическими обозначениями, выделением термина
- `tldr` — содержательный, не "Определение"
- `intuition` — аналогия (скорость→путь), понятная каждому
- `example` — конкретный числовой пример
- `examSay` — что именно сказать на контрольной
- `formula` — без `$$`, чистый KaTeX
- Форматирование: `**bold**`, `\\n`, `$...$`

## 7. Стратегии по типам предметов

### 7.1 Точные науки (Физика, ИиДУ, ЛинАлг)

- `formalText` — строгие математические формулировки с KaTeX
- `steps` — полные доказательства с промежуточными выкладками
- `formula` — ключевая формула крупно
- `conditions` — условия применимости
- `visual` — SVG-диаграмма для ключевых концепций
- `intuition` — физические/геометрические аналогии

**Типы вопросов по баллам:**
- **1 балл** → `type: "Определение"` — краткое определение, без steps
- **3 балла** → `type: "Теорема"` — теорема с ПОЛНЫМ доказательством → `steps` ОБЯЗАТЕЛЬНЫ!
- Без баллов → определяй по контексту: `"Закон"`, `"Понятие"`, `"Формулировка"`

### 7.2 IT-предметы (АЯ C++, ТиМП)

- Код в `<pre class="code-block"><code class="language-cpp">...</code></pre>`
- `intuition` — аналогия из жизни
- `example` — работающий пример кода с комментариями
- `keyIdea` — когда и зачем использовать

### 7.3 Дискретная математика (МОИ)

- Таблицы истинности в HTML-таблицах внутри `formalText`
- `visual` — SVG для контактных схем, диаграмм Хассе
- Формулы в KaTeX: `$\\oplus$`, `$\\|\\mathbf{a}\\|$`

### 8.2 Автоматическая валидация (ОБЯЗАТЕЛЬНАЯ)

После генерации ВСЕХ секций запусти Node.js-скрипт:

```javascript
// Сохрани как /tmp/validate-theory.js и запусти: node /tmp/validate-theory.js
const fs = require('fs');
const path = require('path');

const BASE = 'src/data/<subject>/<assessment>/';
const files = fs.readdirSync(BASE).filter(f => f.startsWith('section-') && f.endsWith('.json'));
const issues = [];

function check(cond, file, id, msg) { if (!cond) issues.push({ file, id, msg }); }

for (const file of files) {
  const data = JSON.parse(fs.readFileSync(path.join(BASE, file), 'utf8'));
  let prevId = 0;

  for (const q of (data.questions || [])) {
    const isTheorem = q.type === 'Теорема' || q.type === 'Формула + вывод';
    const steps = q.steps || [];

    // === Обязательные поля ===
    check(q.title, file, q.id, 'Нет title');
    check(q.type, file, q.id, 'Нет type');
    check(q.formalText, file, q.id, 'Нет formalText');
    check(q.tldr, file, q.id, 'Нет tldr');
    check(q.intuition, file, q.id, 'Нет intuition');
    check(q.keyIdea, file, q.id, 'Нет keyIdea');
    check(q.examSay, file, q.id, 'Нет examSay');

    // === ID последовательные ===
    check(q.id === prevId + 1, file, q.id, `ID не последовательный: ожидали ${prevId + 1}, получили ${q.id}`);
    prevId = q.id;

    // === tldr содержательный ===
    if (q.tldr) {
      check(q.tldr !== q.type, file, q.id, `tldr = type: "${q.tldr}"`);
      check(q.tldr !== 'Определение' && q.tldr !== 'Теорема', file, q.id, `tldr бесполезный: "${q.tldr}"`);
      check(q.tldr.length <= 80, file, q.id, `tldr слишком длинный: ${q.tldr.length} символов`);
    }

    // === Теоремы: steps обязательны ===
    if (isTheorem) {
      check(steps.length >= 3, file, q.id, `Теорема: мало шагов доказательства: ${steps.length}`);
      check(q.example, file, q.id, 'Теорема без example');
    }

    // === HTML-теги запрещены ===
    const allText = [q.formalText, q.tldr, q.intuition, q.keyIdea, q.examSay, q.note].filter(Boolean).join(' ');
    const htmlTags = allText.match(/<(strong|em|br|ol|li|ul|p|div|span)\b/gi);
    if (htmlTags) {
      check(false, file, q.id, `HTML-теги запрещены: ${htmlTags.join(', ')}`);
    }

    // === Unicode math ===
    if (/[αβγδεζηθλμντπρσφχψωΑΒΓΔ∫√∑∏∞≠≈≤≥±∂∇²³¹⁰₀₁₂₃]/.test(allText)) {
      check(false, file, q.id, 'Unicode math в тексте (используй KaTeX)');
    }

    // === Уникальность title шагов ===
    if (steps.length > 0) {
      const titles = steps.map(s => typeof s === 'string' ? s.slice(0, 30) : s.title);
      const uniqueTitles = new Set(titles);
      check(uniqueTitles.size === titles.length, file, q.id,
        `Дубли title шагов: ${titles.filter((t,i) => titles.indexOf(t) !== i).join(', ')}`);
    }

    // === formula без $$ ===
    if (q.formula) {
      check(!q.formula.startsWith('$$'), file, q.id, 'formula начинается с $$ (не нужно)');
      check(!q.formula.endsWith('$$'), file, q.id, 'formula заканчивается на $$ (не нужно)');
    }

    // === Запрещённые фразы ===
    const banned = ['очевидно, что', 'аналогично', 'нетрудно показать', 'легко видеть'];
    for (const phrase of banned) {
      check(!allText.toLowerCase().includes(phrase), file, q.id,
        `Запрещённая фраза: "${phrase}"`);
    }

    // === Проверка LaTeX скобок ===
    const dollars = (allText.match(/(?<!\$)\$(?!\$)/g) || []).length;
    check(dollars % 2 === 0, file, q.id, `Незакрытые $ (нечётное: ${dollars})`);
  }
}

// === Вывод ===
if (issues.length === 0) {
  console.log('✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ! 0 ошибок.');
} else {
  console.log(`❌ НАЙДЕНО ${issues.length} ОШИБОК:\n`);
  for (const i of issues) {
    console.log(`  [${i.id}] ${i.file}: ${i.msg}`);
  }
  console.log(`\n⚠️ ИСПРАВЬ ВСЕ ОШИБКИ ПЕРЕД СБОРКОЙ!`);
}
```

**ОБЯЗАТЕЛЬНО:** запусти и добейся 0 ошибок.

### 8.3 Перечитывание карточек (ОБЯЗАТЕЛЬНАЯ финальная проверка)

> ⚠️ LLM при большом объёме часто делают:
> - Пишут `"tldr": "Определение"` вместо содержательного
> - Пропускают `intuition`
> - Пишут 1-шаговые "доказательства"
> - Используют `<strong>` вместо `**`
> - Сокращают карточки к концу батча

Перечитай **каждую 5-ю карточку** (5, 10, 15, 20...) и проверь:

1. **tldr содержателен** — описывает суть, не тип
2. **intuition полезна** — аналогия из жизни, не формальность
3. **formalText полный** — полное определение/теорема
4. **Нет HTML-тегов** — только markdown
5. **steps полные** — каждый переход объяснён (для теорем)

Если проблема в карточке N — проверь также N-1, N+1.

### 8.4 Антихалтурные правила

| Правило | Зачем |
| --- | --- |
| Батчи по 10 | Промежуточный контроль |
| Каждый tldr уникален | Не пиши одинаковый tldr для похожих карточек |
| Каждый intuition уникален | Не повторяй одну аналогию |
| Проверяй ПОСЛЕДНИЕ карточки | К концу батча качество падает |
| Разнообразь структуру | Не копируй шаблон во все карточки |
| example для КАЖДОЙ теоремы | Теорема без примера бесполезна |
