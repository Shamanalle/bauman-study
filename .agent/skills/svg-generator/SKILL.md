# SVG Generator — Качественная генерация SVG-диаграмм

Этот скилл реализует **итеративный цикл создания SVG** с контролем качества: каждая диаграмма проходит сверку с исходным контентом и доводится до высокого уровня перед переходом к следующей.

## Философия

Ключевой принцип этого скилла — **не количество, а качество**. Каждый SVG должен точно, полно и наглядно передавать содержание исходного материала. Лучше потратить больше времени на один хороший SVG, чем быстро наклепать десять поверхностных.

Аналогия: ты работаешь как иллюстратор учебника — тебе дали текст главы, и ты должен нарисовать такую диаграмму, которую студент посмотрит и **сразу поймёт** суть материала. Если диаграмма не передаёт идею или содержит неточности — её нужно переделать, а не оставлять "и так сойдёт".

## Контекст проекта

### Где хранятся SVG
```
src/public/data/<subject>/svg/<name>.svg
```

### Как они подключаются
В JSON-файлах (`section-XX-*.json`) через поле:
```json
"visual": "svg:img_1",
"visualLabel": "Описание диаграммы для подписи"
```
Лоадер (`src/js/data-loader.js`) загружает SVG по пути `/data/<subject>/svg/<name>.svg` и встраивает inline.

- `physics` — физика (механика, волны, термодинамика)
- `differential-equations` — интегралы и ДУ
- `linear-algebra` — линейная алгебра и ФНП
- `algorithmic-languages` — алгоритмические языки (C++)
- `math-cs-foundations` — математические основы информатики
- `programming-technologies` — технологии и методы программирования

## Стандарты оформления SVG

### Обязательные требования

1. **CSS-переменные для цветов текста** — SVG должны адаптироваться к светлой/тёмной теме:
   - `var(--text)` — основной цвет текста
   - `var(--text2)` — вторичный/серый цвет текста
   - НЕ используй захардкоженные тёмные цвета (`#000`, `#24292f`) — они сломаются в тёмной теме

2. **Акцентные цвета** — используй полупрозрачные заливки для зон:
   - Синий: `stroke="#0969da"`, `fill="rgba(9,105,218,0.15)"`
   - Зелёный: `stroke="#2da44e"`, `fill="rgba(45,164,78,0.15)"`
   - Красный: `stroke="#cf222e"`, `fill="rgba(207,34,46,0.15)"`
   - Оранжевый: `stroke="#bf8700"`, `fill="rgba(191,135,0,0.15)"`
   - Фиолетовый: `stroke="#8250df"`, `fill="rgba(130,80,223,0.15)"`

3. **viewBox и размеры** — всегда задавай `viewBox`, `width` и `height`:
   ```svg
   <svg viewBox="0 0 400 180" width="400" height="180">
   ```
   Стандартная ширина: 400px. Высота адаптивна (140–300px в зависимости от содержимого).

4. **Шрифты**:
   - Формулы, переменные: `font-family="serif"`, `font-style="italic"`
   - Подписи, метки: `font-family="sans-serif"`
   - Код: `font-family="monospace"`
   - Размер: 11–14px для меток, 12–16px для ключевых обозначений

5. **Стрелки для осей** — определяй через `<defs><marker>`:
   ```svg
   <defs>
     <marker id="arr" markerWidth="6" markerHeight="6" refX="5" refY="3" orient="auto">
       <polygon points="0 0, 6 3, 0 6" fill="var(--text2)"/>
     </marker>
   </defs>
   ```

6. **Без внешних зависимостей** — никаких `<image>`, `<use xlink:href>`, внешних шрифтов. Всё inline.

7. **Читаемость при маленьком размере** — SVG часто отображается мелко в карточке. Не перегружай деталями, используй крупные элементы.

## Итеративный цикл создания (КРИТИЧЕСКИ ВАЖНО)

Это ядро скилла. AI-модели часто генерируют SVG с кривыми элементами — текст налезает друг на друга, стрелки указывают не туда, пропорции ломаются. Поэтому цикл включает **обязательную визуальную проверку** через рендеринг в браузере. Без неё SVG не считается завершённым.

Для **каждого** SVG выполняй следующие шаги:

### Шаг 1: Изучение контента
Прочитай исходный материал (JSON-вопрос, текст лекции, пособие), к которому создаётся SVG. Определи:
- Какую **конкретную идею** должна передать диаграмма?
- Какие **элементы** обязательны (формулы, подписи, стрелки, области)?
- Есть ли `visualLabel` — он описывает, что именно нужно визуализировать

### Шаг 2: Создание черновика SVG
Напиши первую версию SVG. Обязательно:
- Соблюдай все стандарты оформления (CSS-переменные, палитра, viewBox)
- Включи все ключевые элементы из контента
- Добавь подписи на русском языке (или с формульными обозначениями)
- Оставляй **запас расстояния** между текстовыми элементами (минимум 20px по вертикали) — AI склонен лепить текст слишком близко

### Шаг 3: Сверка с контентом (текстовая)
Вернись к исходному контенту и **строго сверь** каждый аспект:

| Критерий | Вопрос для проверки |
|----------|-------------------|
| **Точность** | Все ли формулы, обозначения, величины корректны? |
| **Полнота** | Не упущены ли важные элементы, описанные в тексте? |
| **Ясность** | Поймёт ли студент идею, взглянув на диаграмму? |
| **Подписи** | Все ли элементы подписаны? Совпадают ли с текстом? |
| **Контекст** | Соответствует ли диаграмма `visualLabel`? |
| **Стиль** | Соблюдены ли стандарты оформления? |

Если проблемы найдены — исправь и повтори сверку.

### Шаг 4: Визуальная проверка в браузере (ОБЯЗАТЕЛЬНО)

Это **самый важный шаг**, потому что SVG-код может выглядеть логичным, но рендериться криво. AI-модели систематически допускают визуальные баги, которые невозможно обнаружить, просто читая код.

**Процедура:**

1. **Сохрани SVG** во временный HTML-файл для просмотра:
   ```
   Создай файл /tmp/svg_preview.html со следующим содержимым:
   - HTML-обёртка с двумя фонами (светлый и тёмный) для проверки обоих тем
   - CSS-переменные --text, --text2 определены для обеих тем
   - SVG встроен inline дважды — на светлом и на тёмном фоне
   ```

   Шаблон HTML для превью:
   ```html
   <!DOCTYPE html>
   <html>
   <head>
     <style>
       body { margin: 20px; font-family: sans-serif; }
       .preview { padding: 24px; margin: 16px 0; border-radius: 12px; }
       .light {
         background: #ffffff;
         --text: #1a1a2e;
         --text2: #6b7280;
       }
       .dark {
         background: #1a1a2e;
         --text: #e2e8f0;
         --text2: #8b95a5;
       }
       h3 { margin: 8px 0; }
     </style>
   </head>
   <body>
     <h3>🌞 Светлая тема</h3>
     <div class="preview light">
       <!-- ВСТАВЬ SVG СЮДА -->
     </div>
     <h3>🌙 Тёмная тема</h3>
     <div class="preview dark">
       <!-- ВСТАВЬ SVG СЮДА -->
     </div>
   </body>
   </html>
   ```

2. **Открой в браузере** через `browser_subagent` и сделай скриншот (или используй `view_file` если SVG простой и ты уверен в позиционировании).

3. **Оцени визуально** по чек-листу ниже.

**Чек-лист визуальной проверки:**

| Баг | Как выглядит | Как исправить |
|-----|-------------|---------------|
| **Наложение текста** | Буквы/слова перекрывают друг друга | Увеличь расстояние между `<text>` (мин. 20px по Y) |
| **Выход за viewBox** | Элементы обрезаны по краю | Увеличь viewBox или сдвинь элементы внутрь (мин. 10px от края) |
| **Кривые пропорции** | Круги выглядят овалами, квадраты — прямоугольниками | Проверь соотношение viewBox width/height |
| **Стрелки не туда** | Стрелка-маркер повёрнута неправильно | Проверь `orient="auto"` и направление линии |
| **Невидимый текст** | Текст есть в коде, но не виден | Проверь цвет vs фон (var(--text) на светлом/тёмном) |
| **Слипшиеся элементы** | Подписи сливаются с линиями/фигурами | Добавь отступ или фоновую подложку под текст |
| **Текст за пределами фигуры** | Текст должен быть внутри rect, но вылезает | Используй `text-anchor="middle"` и правильные координаты |
| **Кривые Безье уехали** | Кривая идёт совсем не по ожидаемой траектории | Пересчитай контрольные точки; упрости кривую |

4. **Если найдены визуальные баги** — вернись к шагу 2, исправь SVG-код, и снова проверь визуально. Повторяй, пока результат не будет чистым.

### Шаг 5: Финализация
Когда SVG прошёл И текстовую сверку, И визуальную проверку:
1. Сохрани файл в `src/public/data/<subject>/svg/<name>.svg`
2. Если нужно — обнови ссылку `"visual": "svg:<name>"` и `"visualLabel"` в JSON
3. Только после этого переходи к следующему SVG

```
┌──────────────────┐
│  Изучить контент  │
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Создать/исправить│◄──────────────────────┐
│    черновик SVG   │                       │
└────────┬─────────┘                       │
         ▼                                 │
┌──────────────────┐    нет                │
│  Текстовая сверка │──────►  Исправить ───┘
│  с контентом      │                       │
└────────┬─────────┘                       │
         │ ОК                              │
         ▼                                 │
┌──────────────────┐    баги               │
│ ВИЗУАЛЬНАЯ       │──────►  Исправить ───┘
│ ПРОВЕРКА         │
│ (рендер в браузере│
│  + скриншот)      │
└────────┬─────────┘
         │ ОК
         ▼
┌──────────────────┐
│   Сохранить и    │
│   перейти к      │
│   следующему     │
└──────────────────┘
```

## Типы диаграмм и шаблоны

### 1. Графики функций (оси + кривые)
Для: математика, физика, ДУ
```svg
<!-- Оси с маркерами -->
<line ... marker-end="url(#arr)"/>
<!-- Кривые через <path d="M ... C .../> -->
<!-- Закрашенные области через <path ... Z/> с полупрозрачным fill -->
<!-- Подписи осей и ключевых точек -->
```

### 2. Блок-схемы / процессы
Для: информатика, программирование, алгоритмы
```svg
<!-- Прямоугольники с rx скруглением -->
<rect ... rx="6" fill="rgba(9,105,218,0.06)" stroke="#54aeff"/>
<!-- Стрелки-связи между блоками -->
<!-- Текстовые метки внутри блоков -->
```

### 3. Структурные схемы (деревья, графы, иерархии)
Для: ООП (наследование), булевы функции, метрические пространства
```svg
<!-- Узлы = <circle> или <rect> -->
<!-- Рёбра = <line> или <path> -->
<!-- Подписи = <text> -->
```

### 4. Таблицы и матрицы
Для: таблицы истинности, матрицы, сравнения
```svg
<!-- Сетка из <rect> + <text> в каждой ячейке -->
<!-- Заголовки строк/столбцов -->
```

### 5. Физические диаграммы
Для: силы, поля, волны, схемы установок
```svg
<!-- Тела = <circle>, <rect> -->
<!-- Векторы сил = <line> с marker-end -->
<!-- Подписи сил: F, mg, N, и т.д. -->
```

## Защитные практики от типичных AI-багов в SVG

AI-модели при генерации SVG систематически делают одни и те же ошибки. Зная их заранее, можно **избежать** проблем, а не исправлять потом.

### Позиционирование текста
- Всегда используй `text-anchor="middle"` для центрирования текста в фигурах
- Y-координата `<text>` — это **базовая линия** (низ букв), а не верх. Чтобы центрировать текст вертикально в rect высотой H с y=Y, используй `y={Y + H/2}` и `dominant-baseline="central"`
- Для подписей рядом с элементами — оставляй зазор минимум 8px

### Расстояния и отступы
- Минимум 20px по вертикали между строками текста (для font-size 12-14px)
- Минимум 10px от края viewBox до любого контента
- Минимум 8px между текстом и ближайшей линией/фигурой

### Кривые Безье
- Не используй слишком много контрольных точек — чем проще кривая, тем предсказуемее результат
- Проверяй направление: контрольные точки Cubic Bezier (C) «тянут» кривую к себе
- Для простых дуг используй `A` (arc) вместо `C` (cubic bezier)

### Размеры viewBox
- Не делай viewBox слишком тесным — лучше иметь запас пространства
- Стандартный подход: разложи все элементы, посчитай нужные границы, добавь padding 15-20px с каждой стороны

## Частые ошибки — чего избегать

1. **Захардкоженные тёмные цвета** — `fill="#24292f"` будет невидим в тёмной теме. Используй `var(--text)`.
2. **Слишком мелкий текст** — если `font-size < 10`, текст будет нечитаем.
3. **Перегруженность** — больше 15 текстовых элементов в одном SVG — сигнал, что нужно упростить или разбить.
4. **Забытые подписи** — голая диаграмма без подписей бесполезна.
5. **Несоответствие контенту** — SVG показывает не то, что описано в тексте. Именно для этого существует цикл сверки.
6. **Неправильные формулы** — в SVG нельзя использовать LaTeX. Используй Unicode-символы: `∫`, `∑`, `∂`, `α`, `β`, `ω`, `ε`, `Δ`, `→`, `≠`, `≤`, `≥`, `∞`, `⊥`, `∈`, `⊆`.
7. **Пропуск визуальной проверки** — самая опасная ошибка. Код может выглядеть правильным, но рендериться с наложениями и смещениями. ВСЕГДА проверяй визуально.

## Работа с несколькими SVG за раз

Когда нужно создать несколько SVG (например, для всех вопросов раздела):

1. Составь **план**: список SVG с описанием, что каждый визуализирует
2. Подтверди план с пользователем
3. Создавай **последовательно, по одному**: создал → сверил текстово → проверил визуально → исправил → сохранил → перешёл к следующему
4. **НЕ создавай все сразу** — это гарантия низкого качества
5. После завершения всех SVG — обнови JSON-файлы со ссылками

## Чек-лист перед сохранением (финальная проверка)

### Код (текстовая проверка)
- [ ] `viewBox`, `width`, `height` заданы
- [ ] Все текстовые цвета — через `var(--text)` или `var(--text2)`
- [ ] Акценты используют утверждённую палитру
- [ ] Все элементы подписаны
- [ ] Формулы и обозначения совпадают с исходным контентом
- [ ] `visualLabel` в JSON точно описывает содержимое SVG
- [ ] Нет внешних зависимостей
- [ ] Контент сверен с лекцией/пособием

### Визуал (проверка в браузере)
- [ ] Текст не налезает друг на друга
- [ ] Все элементы внутри viewBox (ничего не обрезано)
- [ ] Стрелки и линии указывают в нужном направлении
- [ ] Кривые идут по ожидаемой траектории
- [ ] SVG читается при маленьком размере (не перегружен деталями)
- [ ] Корректно отображается на ОБОИХ фонах (светлый и тёмный)
- [ ] Текст внутри фигур правильно центрирован
