# Practice Mode — Мастер-скилл

Реализация тренировочного и экзаменационного режимов решения задач
для платформы `bauman-study`.

> ### 🎯 Миссия
>
> Ты создаёшь **инструмент тренировки**, по которому студенты МГТУ им. Баумана будут
> готовиться к практической части контрольных, РК и экзаменов. Текущий справочник
> показывает задачи с решениями — но это **чтение**, а не **тренировка**. Студент листает
> решения и думает, что умеет решать. А на контрольной — ступор.
>
> Practice Mode решает две проблемы:
> 1. **«Не умею решать»** — тренировка с подсказками и пошаговым раскрытием
> 2. **«Не успеваю на контрольной»** — симулятор контрольной с таймером
>
> **Качество — не опция, а требование.** Каждая итерация проверяется по 5 осям.
> Итерации бесплатны. Качество — нет.

## 1. Архитектура системы скиллов

Этот мастер-скилл определяет **общую архитектуру**. Конкретная реализация
для каждого предмета описана в **предметных скиллах** (см. §6).

```
practice-mode/SKILL.md              ← ТЫ ЗДЕСЬ (общие контуры)
├── references/
│   ├── physics.md                   ← Физика: специфика задач, формулы, единицы
│   ├── diffeq.md                    ← ИнтДУ: интегралы, ОДУ, вычисления
│   └── linalg.md                    ← ЛинАлг: матрицы, ФНП, доказательства
```

**Алгоритм работы:**
1. Прочитай этот файл целиком
2. Определи предмет (или несколько)
3. Прочитай соответствующий reference-файл из `references/`
4. Изучи существующий код (§2)
5. Реализуй (§3-4)
6. Проверь по итеративному циклу (§5)

### Данные, с которыми работаешь

Каждый practice-бандл содержит 4-5 секций:

| Секция | icon | Содержимое |
|--------|------|-----------|
| section-00-формулы.json | 📋 | Справочные карточки (формулы) |
| section-01-методы.json | 📚 | Алгоритмы решения (шаги) |
| section-02-задачи.json | ✏️ | Задачи с пошаговыми решениями |
| section-03-доп-задачи.json | ✏️ | Дополнительные задачи |
| section-04-билеты.json | 🎫 | Образцы билетов/вариантов |

Каждая задача (sections 02-03) содержит:
- `title` — название/условие
- `type` — тип с темой (`Задача · 3 балла · Площадь (полярные)`)
- `formalText` — полное условие (markdown + KaTeX)
- `hint` — подсказка метода (KaTeX)
- `tldr` — краткое описание метода
- `steps[]` — пошаговое решение (`title`, `text`, `math`)
- `formula` — финальный ответ (чистый LaTeX)

## 3. Два режима: Тренировка и Контрольная

### 3.1 Как студент попадает в режим

Добавь новый mode — `practice-training` — доступный через:
- URL-параметр: `?mode=practice-training` (аналогия с `?mode=flashcard`)
- Или через переключатель табов в practice-browser (рядом с «Карточки» / «Повторение»)

Для контрольной: `?mode=exam-sim` или кнопка в том же переключателе.

### 3.2 Тренировка (Training Mode)

**Поток:**
```
Setup → [Справочник опционально] → Задача 1 → Задача 2 → ... → Результаты
```

**Setup-экран:**
- Карта покрытия по темам (progress bars)
- Выбор темы: конкретная или «Все вперемешку»
- Размер сессии: 5 / 10 / 15 задач
- Режим: «Новые» / «Слабые места» / «Все»
- Кнопка «📖 Справочник» — показывает формулы/методы перед стартом

**Task-экран (одна задача):**
```
┌─────────────────────────────────┐
│  3/10         ████████░░        │  ← прогресс
├─────────────────────────────────┤
│  Задача · 3 балла · Площадь     │  ← тип
│                                 │
│  Вычислить площадь фигуры,      │  ← formalText
│  ограниченной кривой...         │
│  $$r = a\cos 3\varphi$$         │
│                                 │
│  [💡 Подсказка]                 │  ← hint (метод)
│  [✅ Показать решение]          │
├─────────────────────────────────┤
│  (решение раскрывается)         │
│  (1) Анализ...                  │
│  (2) Формула площади...         │
│  (3) Вычисление...              │
│  (4) Ответ: □ 3πa²/8           │
│                                 │
│  [✅ Понял]    [❌ Не понял]    │
└─────────────────────────────────┘
```

**Results-экран:**
- Итог: 7/10 понял, 3 не понял
- Разбивка по темам
- Список «слабых» задач
- Кнопка «🔄 Повторить слабые»

### 3.3 Контрольная (Exam Simulator)

**Поток:**
```
Setup (выбор билета или генерация) → Все задачи + таймер → Сверка
```

**Setup:**
- Если есть section-04-билеты.json — предложить реальный билет
- Или «Случайный билет» — N задач из разных тем
- Таймер: выбор (45 / 60 / 90 мин)

**Exam-экран:**
```
┌─────────────────────────────────┐
│  ⏱ 01:12:34        Билет       │
│  [1] [2] [3] [4] [5]           │  ← навигация (кликабельная)
│   ●   ○   ○   ○   ○            │
├─────────────────────────────────┤
│  Задача 1:                      │
│  ∫ x·eˣ dx                     │  ← условие (без подсказок!)
│                                 │
│  [→ Следующая]                  │
└─────────────────────────────────┘
```

*Никаких подсказок и решений до завершения.*

**Сверка (после завершения):**
- Все задачи + решения
- Для каждой: «✅ Решил верно» / «❌ Ошибся»
- Итоговый процент
- «Потрачено: 47 мин из 90»

### 3.4 Справочник в хедере

Не отдельный экран — кнопка «📖» в хедере тренировки и контрольной.
Нажатие открывает slide-over panel со справочными карточками и алгоритмами.
На контрольной — доступен только первые 2 минуты (потом скрывается, как на реальном экзамене).

## 4. Техническая архитектура

### 4.1 Новые JS-модули

| Модуль | Ответственность |
|--------|---------------|
| `practice-engine.js` | Логика сессий: выбор задач, фильтрация по темам, прогресс, слабые места |
| `practice-training.js` | UI тренировочного режима |
| `exam-simulator.js` | UI контрольной-симулятора |

### 4.2 practice-engine.js (чистая логика)

```js
// Основные функции:
buildSession(questions, options)    // Собрать сессию из N задач
markResult(questionId, understood)  // Записать результат
getTopicStats()                     // Статистика по темам
getWeakTopics()                     // Темы, где студент слаб
generateRandomTicket(sections, n)   // Случайный билет из N задач
```

Хранение прогресса:
```
localStorage['prac-{shortCode}-results']  = { questionId → { understood, timestamp }[] }
localStorage['prac-{shortCode}-sessions'] = { sessionId, date, score, duration }[]
```

### 4.3 Стили

Добавь стили в существующие файлы:
- CSS переменные из `base.css`
- Dark theme overrides в `dark.css`
- Можно создать `practice-training.css` если объём большой

### 4.4 Ограничения

- **Vanilla JS** — ES modules, никаких фреймворков
- **Offline** — только localStorage
- **Переиспользуй** существующие модули (math-utils, text-utils, practice-browser.md)
- **CSS-переменные** — нет хардкода цветов
- **Dark theme** — обязательна
- **Мобильный UX** — кнопки крупные, всё читаемо на 320px
- **Горячие клавиши** — Space/Enter для раскрытия, 1/2 для оценки

## 5. Итеративный цикл самоулучшения

> **Это самая важная часть.** Не сдавай после первой реализации.

```
iteration = 0

while (true) {
  iteration++

  // ── РЕАЛИЗАЦИЯ ──
  if (iteration == 1) {
    Engine → Training UI → Exam UI → Стили → Интеграция
  } else {
    Применить улучшения найденные на предыдущей итерации
  }

  // ── ВЕРИФИКАЦИЯ ──
  npm run build → 0 ошибок
  Открой в браузере → проверь ВСЕ экраны
  Пройди тренировку (5-8 задач) как студент
  Пройди контрольную (3 задачи) с таймером
  Проверь dark theme
  Проверь edge-cases (пустой бандл, все решены, первый визит)

  // ── РЕФЛЕКСИЯ — 5 осей ──

  1. КОНТЕНТ — ПРАВИЛЬНО ЛИ ОТОБРАЖАЕТСЯ?
     - KaTeX формулы рендерятся? Не обрезаются?
     - formalText полностью виден? Markdown работает?
     - Steps пошагово раскрываются? math внутри шагов?
     - Для КАЖДОГО предмета: физика (формулы + единицы),
       ИнтДУ (длинные вычисления), ЛА (матрицы).
     - Графики (plot) рендерятся для геометрических задач?

  2. ПЕДАГОГИКА — ЭТО ЛУЧШИЙ ВАРИАНТ ДЛЯ ОБУЧЕНИЯ?
     Встань на место студента ЗА ДЕНЬ до контрольной.
     - Помогает ли тренировка РЕАЛЬНО научиться решать?
     - Справочник перед задачами — достаточно? Или нужно больше контекста?
     - «Понял / Не понял» — студент будет честен? Может нужен третий вариант?
     - Слабые места определяются корректно? Рекомендации полезны?
     - Контрольная-симулятор — ощущается как реальная? Не как игрушка?
     - Таймер — мотивирует или пугает? Правильная ли механика?
     - **Есть ли способ сделать обучение эффективнее?**

  3. ЛАКОНИЧНОСТЬ — НЕТ ЛИ ЛИШНЕГО?
     - Каждый элемент на экране несёт смысл?
     - Путь от «открыл бандл» до «начал решать» — минимальный?
     - Setup не перегружен? Карта покрытия читаемая?
     - Визуально — аккуратно и современно? Не «курсовая из 2015»?

  4. ФУНКЦИОНАЛЬНОСТЬ
     - Прогресс сохраняется между сессиями?
     - Горячие клавиши работают?
     - Dark theme — всё видно?
     - Навигация по задачам в контрольной — удобная?
     - Таймер точный? Пауза работает?
     - Edge-cases: пустой бандл, первый визит?

  5. КОД
     - Не дублирую practice-browser.js? Переиспользую md(), renderMath()?
     - CSS через переменные?
     - Модули чистые? Engine без UI?

  // ── РЕШЕНИЕ ──
  // «Это лучшее, что я могу сделать?»
  // Не «работает ли?» — а «ЭТО ЛУЧШЕЕ?»

  if (нашёл проблему ИЛИ нашёл стоящее улучшение) {
    Запиши что улучшить → continue
  } else {
    break
  }
}
```

## 6. Предметные reference-файлы

Перед реализацией для конкретного предмета — **обязательно** прочитай
соответствующий файл из `references/`. Там описана специфика:

| Предмет | Файл | Ключевая специфика |
|---------|------|----|
| Физика | `references/physics.md` | Формулы с единицами, графики, задачи на применение законов |
| ИнтДУ | `references/diffeq.md` | Длинные вычисления, цепочки замен, типы ОДУ |
| ЛинАлг + ФНП | `references/linalg.md` | Матрицы, квадратичные формы, экстремумы ФНП |

Каждый reference содержит:
1. **Типы задач** конкретного предмета
2. **Как адаптировать UI** — какие элементы важнее
3. **Специфика данных** — какие поля используются, особенности
4. **Примеры** реальных задач

## 7. Антипаттерны

- ❌ Копировать HTML-построение вместо переиспользования `md()` из practice-browser
- ❌ Хардкодить цвета вместо CSS-переменных
- ❌ Не вызывать `renderMath()` после вставки HTML
- ❌ Дефолтная сессия из 50 задач — студент устанет после 10
- ❌ Нет анимаций — интерфейс кажется «мёртвым»
- ❌ Таймер не видно — студент забывает про время
- ❌ Одинаковый UX для тренировки и контрольной — разные задачи, разный UX
- ❌ «Готово!» после первой реализации без ревизии
- ❌ Не тестировать на разных предметах — проверяй минимум 3
