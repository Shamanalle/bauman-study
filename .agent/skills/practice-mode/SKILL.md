# Practice Mode — Мастер-скилл

> ### 🎯 Миссия
>
> Ты создаёшь **инструмент, который научит студентов решать задачи.**
>
> Не «покажет решения» — этот режим уже есть (practice-browser.js). А именно **научит**.
> Разница огромная: студент может прочитать 50 решений и не решить ни одной задачи
> на контрольной. Потому что «читать» и «решать» — разные когнитивные навыки.
>
> Твоя задача — создать мост между «смотрю решение» и «решаю сам». Через активное
> вовлечение: подумай → попробуй → проверь → оцени себя → повтори слабое.
>
> **Это реальные студенты МГТУ им. Баумана.** Контрольные через неделю. Если твой
> тренажёр не работает — они получат плохие оценки. Если работает — они придут
> на контрольную и скажут «о, это же как в тренажёре, я знаю как решать».
>
> **Нет лимита на итерации.** Делай столько итераций, сколько нужно, чтобы результат
> стал по-настоящему хорошим. Компромисс между качеством и скоростью — всегда
> в пользу качества. Лучше 5 итераций и wow-результат, чем 1 итерация и «сойдёт».

| ЛинАлг + ФНП | `practice-linalg/SKILL.md` | Тренажёр линалга и ФНП |

**Алгоритм:**
1. Прочитай этот мастер-скилл полностью
2. Определи предмет
3. Прочитай **соответствующий предметный скилл** — там специфика, типы задач,
   адаптации UI и предметный цикл качества
4. Изучи кодовую базу (§2)
5. Реализуй, следуя итеративному циклу (§5)

- `formula` — финальный ответ

## 3. Два режима: Тренировка и Контрольная

### 3.1 Тренировка

**Суть:** студент решает задачи по одной на бумаге, проверяет себя, система отслеживает прогресс.

**Поток:** Setup → [Справочник?] → Задача → ... → Результаты

**Ключевые элементы:**
- **Выбор темы** — студент выбирает конкретную тему или «все вперемешку»
- **Карта покрытия** — прогресс по темам (progress bars), видно где слабые места
- **Задача** — показать условие → студент решает на бумаге → раскрыть решение
- **Подсказка** — кнопка «💡 Подсказка» показывает hint (метод, не ответ)
- **Самооценка** — после раскрытия: «✅ Понял / ❌ Не понял»
- **Результаты** — итог сессии, список слабых тем, кнопка «🔄 Повторить слабые»

### 3.2 Контрольная (Exam Simulator)

**Суть:** имитация реальной контрольной/экзамена — несколько задач, таймер, никаких подсказок.

**Поток:** Setup (билет + таймер) → Все задачи + ⏱ → Сверка

**Ключевые элементы:**
- **Билет** — из section-04 или случайный набор из section-02/03
- **Таймер** — видимый! 45/60/90 минут на выбор
- **Навигация** — кликабельные номера задач (как на реальном экзамене)
- **Никаких подсказок** до завершения
- **Сверка** — после завершения: все задачи + решения + self-check per задачу

### 3.3 Справочник

Не отдельный экран — кнопка «📖» в хедере. Slide-over с формулами и алгоритмами.
(В контрольной можно ограничить доступ — как на реальном экзамене.)

## 4. Как думать (творческая свобода)

У тебя **полная свобода** в проектировании UX. Вот вопросы для размышления —
не инструкции, а пища для мысли. Если придумаешь лучше — делай.

### Про поток тренировки

- Как студент попадает в режим? Таб? Кнопка? URL? Что естественнее для существующего UI?
- Справочник перед задачами — автоматически (как warmup) или по кнопке? Зависит ли от предмета?
- Размер сессии — 5? 10? 15? Зависит ли от количества задач в бандле?
- Что если все задачи решены? Как мотивировать повторение?
- Стоит ли группировать задачи по сложности (1 балл → 3 балла)?

### Про самооценку

- «Понял / Не понял» — достаточно? Или стоит 3 уровня (не знаю / частично / знаю)?
- Как помочь студенту быть **честным**? Он видит решение и думает «ну да, я бы так и сделал»,
  хотя на самом деле застрял бы. Есть ли способ подтолкнуть к честной оценке?
- Стоит ли показывать «степень уверенности» перед раскрытием?

### Про контрольную

- Показывать ли все задачи сразу (как на реальной контрольной) или по одной?
- Что если таймер истёк? Мягкое предупреждение? Принудительное завершение?
- Стоит ли показывать результаты предыдущих контрольных?
- Есть ли смысл в «паузе» для контрольной? Или это ломает реализм?

### Про разные предметы

Каждый предмет — свои задачи, своя специфика:
- ИнтДУ: длинные цепочки замен, ключевое — определить метод
- Физика: определить закон, подставить числа, проверить размерность
- ЛинАлг: матрицы, системы, два разных блока (алгебра + ФНП)

**Подумай: нужна ли адаптация тренировочного UX под предмет?**
Может, для ИнтДУ подсказка метода важнее, чем для физики?
Может, для ЛА нужен другой формат справочника?

Предметные скиллы (`practice-diffeq/`, `practice-physics/`, `practice-linalg/`)
содержат специфику — прочитай их для конкретного предмета.

## 5. Итеративный цикл самоулучшения

> **Это ядро скилла.** Первая реализация — всегда черновик. Качество рождается
> в итерациях. Не сдавай работу, пока не пройдёшь весь цикл.

```
iteration = 0

while (true) {
  iteration++

  // ── РЕАЛИЗАЦИЯ ──
  if (iteration == 1) {
    Полная реализация: Engine → Training UI → Exam UI → Стили
  } else {
    Применить улучшения с предыдущей итерации
  }

  // ── ВЕРИФИКАЦИЯ ──
  npm run build → 0 ошибок
  Открой в браузере → проверь КАЖДЫЙ экран
  Пройди тренировку (5-8 задач по одному предмету) как студент
  Пройди контрольную (3 задачи + таймер)
  Проверь dark theme
  Проверь edge-cases (пустой бандл, первый визит, всё решено)

  // ── РЕФЛЕКСИЯ — 5 ОСЕЙ ──

  1. КОНТЕНТ — ПРАВИЛЬНО ЛИ ОТОБРАЖАЕТСЯ?
     Открой тренировку для нескольких разных предметов:
     - KaTeX формулы — рендерятся? Не обрезаны? Матрицы влезают?
     - formalText — полностью видно? Markdown (жирный, списки) работает?
     - Steps — раскрываются? math внутри шагов рендерится?
     - Графики (plot) — если есть, рендерятся?
     - hint — содержательный? Показывает метод, а не ответ?
     
     Проверь КОНКРЕТНО: ИнтДУ (длинные замены), физику (единицы),
     ЛА (матрицы pmatrix). Не проверяй на одном предмете.

  2. ПЕДАГОГИКА — ЭТО ЛУЧШИЙ ВАРИАНТ ДЛЯ ОБУЧЕНИЯ?
     Встань на место студента ЗА ДЕНЬ до контрольной.
     - Помогает ли мой тренажёр РЕАЛЬНО научиться решать?
     - Или студент просто тычет «Показать решение» → «Понял» без обдумывания?
     - Справочник — доступен? Достаточен? Или студент уходит гуглить?
     - Карта покрытия — мотивирует? Или пугает (80% красного)?
     - Контрольная — ощущается как реальная? Или как игрушка?
     - **Ключевой вопрос: есть ли способ сделать обучение эффективнее?**
       Может, стоит показать тип задачи ДО раскрытия (чтобы студент попробовал
       определить метод сам)? Может, стоит показывать один шаг за раз?
       Может, связать теорию и практику (ссылка на теоретическую карточку)?

  3. ЛАКОНИЧНОСТЬ — НЕТ ЛИ ЛИШНЕГО?
     - Каждый элемент на экране несёт смысл?
     - Setup не перегружен? Студент быстро начинает решать?
     - Нет ли лишних кликов, модалов, промежуточных экранов?
     - Визуально — аккуратно и современно?
       Или как студенческая курсовая 2015 года?
     - Анимации — есть? Плавные? Не избыточные?

  4. ФУНКЦИОНАЛЬНОСТЬ
     - Прогресс сохраняется между сессиями (localStorage)?
     - Горячие клавиши работают (Space, Enter, 1/2)?
     - Dark theme — всё видно, цвета не сливаются?
     - Таймер контрольной — точный? Виден? Не мешает?
     - Навигация по задачам в контрольной — удобная?
     - Мобильный UX — кнопки крупные, текст читаемый на 320px?
     - Edge-cases: 0 задач, первый визит, все решены, один тип задач?

  5. КОД
     - Не дублирую practice-browser.js? Переиспользую md(), renderMath()?
     - CSS через переменные, не хардкод?
     - Engine отделён от UI?
     - Модули чистые, без side effects при импорте?

  // ── РЕШЕНИЕ ──
  // Ответь ЧЕСТНО на один вопрос:
  //
  // «Если бы я был студентом за день до контрольной —
  //  я бы ХОТЕЛ тренироваться через этот инструмент?
  //  Или пошёл бы решать в тетрадке?»
  //
  // Если хоть тень сомнения — значит, можно лучше.

  if (нашёл проблему ИЛИ нашёл улучшение ИЛИ не уверен) {
    Запиши что улучшить → continue
  } else {
    // Финальная проверка: открой браузер ещё раз.
    // Пройди 3-5 задач. Если и после этого ничего — заканчивай.
    break
  }
}
```

### 5.1 Примеры находок на ревизии

**Контент:**
- «Матрица 4×4 обрезается на мобильном → нужен overflow-x scroll на math-box»
- «Hint показывает ответ вместо метода → переписать hint-отображение»
- «formalText физической задачи без «Дано:» — непонятно что искать»

**Педагогика:**
- «Студент жмёт «Понял» не думая — может, добавить delay перед кнопками?»
- «Справочник открывается в модале и закрывает условие — нужен side panel»
- «После 10 задач устаёт — может, 8 по умолчанию?»
- «Нет связи теория↔практика: студент застрял, а перейти к теории не может»

**Лаконичность:**
- «7 элементов на setup-экране — перегруз. Оставлю 3 + шестерёнку»
- «Текст «Нажмите Enter для продолжения» — он и так видит кнопку»
- «Progress bar + текстовый счётчик + процент — избыточно, хватит двух»

## 6. Технические ограничения

- **Vanilla JS** — ES modules, никаких фреймворков
- **Offline** — только localStorage, никакого сервера
- **Переиспользуй** существующие модули (md(), renderMath(), nl(), progress)
- **CSS-переменные** из base.css — нет хардкода цветов
- **Dark theme** — обязательна
- **Мобильный UX** — кнопки крупные, всё читаемо на 320px
- **Горячие клавиши** — Space/Enter для раскрытия, числа для оценки

## 7. Антипаттерны

- ❌ Копировать HTML вместо переиспользования `md()` из practice-browser
- ❌ Хардкодить цвета (`#ff0000`) вместо CSS-переменных
- ❌ Не вызывать `renderMath()` после вставки HTML с формулами
- ❌ Забыть про `progress.setPrefix()` — данные перемешаются между бандлами
- ❌ Сессия по умолчанию из 50 задач — студент устанет после 10
- ❌ Нет анимаций — интерфейс кажется «мёртвым»
- ❌ Одинаковый UX для тренировки и контрольной — разные цели, разный UX
- ❌ Не тестировать на разных предметах — проверь минимум для 3 предметов
- ❌ «Готово!» после первой реализации без единой ревизии
- ❌ Таймер не видно — студент забывает про время
