1. 
Концепции (принципы) ООП 
 
Инкапсуляция – заключение переменных и функций, относящихся к одной сущности, в единый 
объект («капсулу») и регулирование доступа к ним со стороны других сущностей. Иногда заключение 
переменных и функций в единый объект выделяют в отдельную концепцию – абстракцию 
(абстрагирование). 
Наследование – механизм, позволяющий определить новые классы на базе уже существующих 
(«наследуя» их поля и методы и расширяя их функционал). 
Полиморфизм – механизм, позволяющий создавать различные реализации одноимённых 
методов и вызывать «подходящую» версию в зависимости от типов параметров и/или объекта. 
2. 
Виды полиморфизма 
В теме «Наследование» вы уже познакомились с переопределением методов (введение нового 
определения в классе-наследнике), и вызывали их в объектах-наследниках. Таким образом, вы 
создавали методы с одинаковыми названиями, но разным функционалом. И это подходит под 
определение полиморфизма   
Переопределение методов в классах-наследниках и уже знакомый вам механизм шаблонов – это 
проявление статического полиморфизма. т.к. то, какой метод будет вызван для объекта, известно на 
этапе компиляции. 
Если есть статический полиморфизм, то должен быть и динамический? И он есть  
Динамический полиморфизм проявляется тогда, когда конкретный метод определяется уже во время 
работы программы.  
С полиморфизмом тесно связано понятие связывания – сопоставление вызова функции с её 
определением. В зависимости от типа полиморфизма выделяют соответственно раннее (статическое) 
и позднее (динамическое) связывание. 
Примеры полиморфизма приведены в примере 1 с классами прямоугольника и прямоугольного 
параллелепипеда. В строке 44 срабатывает статический полиморфизм: вызывается переопределённый 
метод класса-наследника. В строках 45 и 47 создаются указатель и ссылка типа базового класса, в 
которые помещаются адрес и объект производного класса соответственно. В строках 46 и 48 для них 
вызываются методы для подсчёта площади, и срабатывает метод родительского класса.

#include <iostream> 
 
class Rectangle 
{ 
protected: 
    float length; 
    float width; 
public: 
    Rectangle(const float &l = 0, const float &w = 0) : length(l), width(w) {} 
    float countPerimeter() const 
    { 
        return 2 * (length + width); 
    } 
    float countArea() const 
    { 
        return length * width; 
    } 
}; 
 
 
 
class Parallelepiped : public Rectangle 
{ 
    float height; 
public: 
    Parallelepiped(const float &l = 0, const float &w = 0, const float &h = 0) 
        : Rectangle(l, w), height(h) {} 
    float countPerimeter() const 
    { 
        return 4 * (length + width + height); 
    } 
    float countVolume() const 
    { 
        return length * width * height; 
    } 
    float countArea() const 
    { 
        return 2 * (length * width + length * height + width * height); 
    } 
}; 
 
int main() 
{ 
    Parallelepiped p(1, 2, 3); 
    std::cout << "p's area: " << p.countArea() << std::endl; 
    Rectangle* r = &p; 
    std::cout << "r's area: " << r->countArea() << std::endl; 
    Rectangle& r2 = p; 
    std::cout << "r2's area: " << r2.countArea() << std::endl; 
    return 0; 
}

class Rectangle

    float length; 
    float width;

    Rectangle(const float &l = 0, const float &w = 0) : length(l), width(w) {} 
    virtual float countPerimeter() const 
    { 
        return 2 * (length + width);

Стоит отметить, что если при переопределении функции не объявить виртуальными, они 
таковыми всё равно будут являться (т.к. в родительском классе были виртуальными). 
Для работы динамического полиморфизма кол-во параметров, их типы, а также тип 
возвращаемого значения для методов должны полностью совпадать. Переопределением 
константного метода может являться только константный метод, неконстантного – 
неконстантный. Из этого правила есть только одно исключение – когда типом возвращаемого 
значения является указатель или ссылка на текущий класс. 
Чтобы не иметь проблем, связанных с различиями в параметрах методов (типах параметров, 
константности метода), настоятельно рекомендуется в конце объявления переопределённой 
функции добавлять ключевое слово override (пример 3). В случае несовпадения прототипов 
методов код не скомпилируется.

3. 
Как это работает? 
При компиляции для каждого класса, содержащего виртуальные методы или наследованного от 
класса, имеющего виртуальные методы, создаётся скрытый член – таблица виртуальных методов, в 
которой для каждого виртуального метода содержится адрес памяти, по которому находится 
подходящая реализация метода. Если метод переопределён в наследнике, в его таблице виртуальных 
методов будет указан адрес переопределения, а если не был переопределён, то адрес метода из класса-
родителя. 
4. 
Полиморфизм при создании и уничтожении объектов 
При вызовах виртуальных функций в конструкторах и деструкторах всегда будет вызываться 
метод из родительского класса. Это связано с тем, что создание объекта начинается с родительской 
части, а уничтожение – с части наследника, поэтому к моменту вызова метода в теле конструктора 
часть от наследника ещё не будет создана, а в теле деструктора – уже будет уничтожена. 
+1 к best practices: не вызывайте виртуальные методы в конструкторах и деструкторах. 
5. 
Виртуальные деструкторы 
С учётом новых знаний о работе с объектами-наследниками через ссылки и указатели 
родительского класса может возникнуть вопрос: раз мы можем объявить указатель типа родительского 
класса на объект производного класса, то что будет происходить, если попытаться освободить 
память через указатель родительского класса? 
Исходя из опыта с обычными функциями, на этот вопрос можно ответить без подвоха: если 
деструктор не объявлен как виртуальный, будет вызван деструктор по типу указателя, т.е. 
деструктор родительского класса. Если объект имеет собственные динамические поля, произойдёт 
утечка памяти. Выход из этой ситуации – объявления деструктора виртуальным (а вот конструкторы 
виртуальными быть не могут). 
+1 к best practices: если планируете наследоваться от класса, объявляйте его деструктор 
виртуальным.

6. 
А зачем это нужно? 
Это главный вопрос, который должен был остаться после прочтения вышеизложенного. Зачем 
объявлять указатель или ссылку родительского типа на объект типа наследника? 
Как вы помните, есть достаточно много структур данных, позволяющих работать с множеством 
объектов (статический массив, динамический массив, вектор, очередь, список, множество и т.д.), но 
все они работают с объектами одного типа.  
Динамический полиморфизм позволяет в рамках одной структуры-множества работать с 
объектами разных типов, объединёнными общим предком, причём делать это единообразно (через 
одни и те же функции). Например, как в примере 5: в первом цикле накидали в вектор прямоугольников 
и параллелепипедов, а во втором вывели на экран параметры, периметр и площадь для всех фигур, не 
задумываясь о том, к объекту какого типа идёт обращение. Методы печати, само собой, должны быть 
предварительно объявлены в классах, причём как минимум метод Rectangle должен быть объявлен 
виртуальным.

Чистые виртуальные функции и абстрактные классы 
Есть особая разновидность виртуальных функций, которые не имеют определения в 
родительском классе и должны быть определены в классе-наследнике. Такие функции называются 
чистыми виртуальными функциями. В примере 6 методы countPerimeter и countArea класса 
Figure являются чистыми виртуальными функциями: им «присвоено» значение 0.

class Figure 
{ 
public: 
 
virtual float countPerimeter() const = 0; 
 
virtual float countArea() const = 0; 
}; 
 
class Rectangle : public Figure 
{ 
protected: 
 
float length; 
 
float width; 
public: 
 
Rectangle(const float &l = 0, const float &w = 0) : length(l), width(w) {} 
 
float countPerimeter() const override 
 
{ 
 
 
return 2 * length * width; 
 
} 
 
float countArea() const override 
 
{ 
 
 
return length * width; 
 
} 
}; 
Т.к. функция не определена, её нельзя использовать. Следствие этого – нельзя создать объект 
класса, который имеет хотя бы одну чистую виртуальную функцию. Такие классы называются 
абстрактными классами. Если в наследнике абстрактного класса чистая виртуальная функция не 
определена, этот класс тоже будет абстрактным.  
Однако вне класса чистую виртуальную функцию можно определить, как показано в примере 
7. Непосредственно в теле класса функция так и остаётся с «присвоением» 0, класс остаётся 
абстрактным. В этом случае классы-наследники до переопределения методов будут являться 
абстрактными классами, но смогут использовать «реализацию по умолчанию», явно вызывая её через 
имя родительского класса (Figure::countPerimeter()). 
Абстрактные классы нужны для задания некоторого «шаблона». Сами по себе, в отрыве от 
наследников, они могут не иметь смысла. Например, фигура без параметров не имеет смысла, но 
отсутствие полей вроде «сторона» в базовом классе позволяет определять более разных наследников 
(например, круг не имеет сторон, но имеет периметр и площадь, объявленные в родительском классе). 
Несмотря на то, что нельзя создать объект фигуры, этот тип данных можно использовать для работы с 
объектами-наследниками (указатели и ссылки не порождают новые объекты, а значит могут иметь тип 
абстрактного класса).

8. 
Интерфейс 
Интерфейс – это класс, не имеющий полей, все методы которого являются чистыми 
виртуальными функциями. 
В C++ нет специального ключевого слова для объявления интерфейсов (как, например, в C#), 
они определяются как обычные абстрактные классы. Например, класс Figure из примера 6 является 
интерфейсом.  
9. 
Доступ к полям наследника через родительский класс 
У динамического полиморфизма есть неприятная сторона: указатель/ссылка родительского 
типа «видит» только свои поля и методы. Таким образом, становится затруднительно вызвать те 
методы, которые есть только в классе-наследнике. 
Из этой ситуации есть 2 выхода: 
1) добавить соответствующую виртуальную функцию в базовый класс; 
2) использовать преобразование (приведение) указателя или ссылки к типу производного 
типа (указателю или ссылке). 
Первый подход плох для узкоспециализированных функций наследника, поскольку 
производные классы зависят от базового, но базовый не должен зависеть от производных. Например, 
довольно странно в класс фигуры будет добавлять метод для вычисления диаметра, поскольку такие 
характеристики, как радиус и диаметр есть только у специфичных типов фигур. В подобных случаях 
стоит использовать второй подход. 
Преобразование типа также имеет свои ограничения: оно не преобразует классы, не имеющие 
виртуальных таблиц (т.е. ни одного виртуального метода), и классы, использующие виртуальное или 
private- или protected-наследование. 
Преобразование типов обеспечивает dynamic_cast. Если преобразование типа не удалось, 
dynamic_cast возвращает nullptr.
