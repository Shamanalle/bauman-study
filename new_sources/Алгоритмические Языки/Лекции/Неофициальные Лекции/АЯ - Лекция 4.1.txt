Исключения 
1. 
Основная терминология 
Исключение – это некоторый нестандартный случай (исключительная ситуация), который не 
может быть обработан. 
Исключение в С++ – это объект некоторого типа, который генерируется в исключительной 
ситуации.  
С исключениями связаны 3 оператора:  
 throw («бросать» / «кидать») 
 try («пробовать» / «пытаться») 
 catch («ловить» / «поймать») 
Оператор throw, как следует из названия, позволяет «бросать» (генерировать) исключение. За 
этим оператором должен быть указан объект, который будет брошен. Это может быть как объект 
стандартного типа, так и объект пользовательского типа. Объект может определяться сразу после 
оператора throw, также можно бросать ранее определённые переменные. 
Внутри оператора try помещается блок кода, в котором может генерироваться исключение, 
которое мы хотим поймать.  
В блоке оператора catch помещается код, который должен выполниться, если исключение 
произошло и было «поймано». В качестве параметра catch передаётся тип исключения, которое 
должно быть поймано, или многоточие – если должно быть поймано исключение любого типа. 
Параметры блока catch аналогичны параметрам функций – их так же можно передавать по значению 
и по ссылке, они тоже могут быть константными. После выполнения кода в блоке catch выполняется 
код, следующий за этим блоком. 
2. 
Основные механизмы использования 
Простой пример – деление на ноль – приведён в примере 1. В блоке try помещён код, 
генерирующий исключение. Если делитель равен нулю, то «бросаем» -1 (строка 13). Т.к. в блоке 
catch стоит многоточие и ловятся все исключения, программа ловит -1 и выводит сообщение о 
делении на 0 (строка 19). Данный пример носит иллюстративный характер. Какие исключения в каких 
ситуациях бросать правильно, будет рассмотрено позднее. 
У блока try должен быть хотя бы один catch! Блоков catch может быть несколько, они 
должны отличаться типами параметров (пример 2). Если бросаемое значение не будет использовано и 
важен только тип исключения, может быть указан только тип значения (пример 3), если значение будет 
использовано, то необходимо указать название для переменной, куда будет помещено значение 
(пример 4). 
Поиск подходящего блока catch осуществляется последовательно, так что в случае 
использования универсального catch (с многоточием), он должен быть размещён самым 
последним.

Кидать исключение не обязательно непосредственно в блоке try. Код, бросающий 
исключение, может находиться в функции, которая вызывается внутри блока try. Уровень 
вложенности может быть любым: когда генерируется исключение и блок try не находится внутри 
функции, где сгенерировано исключение, блок ищется в «вышестоящей» функции, если не найден там 
– ещё в более «вышестоящей», и т.д., пока не найдётся блок try или не закончатся в функции. Если 
поиск дошёл до main, и там тоже нет try, исключение считается необработанным, программа падает 
(завершается аварийно). Пример с бросанием исключения в функции – в примере 5.

3. 
Исключения и ООП 
Разумеется, мы не просто так говорим об исключениях во втором семестре  
Несмотря на то, что большинство из вас не кидало исключения, едва ли кто-то с ними не 
сталкивался, когда его программа падала. 
Стандартные библиотеки генерируют множество исключений, которые являются наследниками 
класса std::exception. В этом классе есть виртуальный метод с говорящим названием what, с 
помощью которого можно получить строку-пояснение (const char*), которая может быть задана 
реализацией what либо может быть взята из некоторого поля класса.  
Наследники std::exception разделены по ситуациям, в которых они возникают. Например, 
исключения типа std::logic_error и его наследники возникают в случаях, когда возникла 
ошибка, связанная с неправильной логикой работы программы. Так, в случае неправильного аргумента 
вызывается std::invalid_argument. Именно это исключение было бы более подходящим в 
примере с делением на 0.

Стоит обратить внимание, что «ловля» исключения происходит через ссылку на 
std::exception (строка 22). Этот механизм работает только в случае, когда генерируется 
исключение-наследник, а «ловится» исключение базового класса. В обратную сторону (генерируется 
«родитель», ловится «наследник») не работает. Также обращаю внимание, что для того, чтобы в этом 
случае гарантированно было выведено верное сообщение об ошибке, должен сработать динамический 
полиморфизм, для чего необходимо «ловить» исключение по ссылке. В противном случае результат 
будет зависеть от реализации используемой вами версии стандартных библиотек (если там what для 
std::exception выводит строковую константу, а не значение поля, то будет выведена константа, а 
переданное в конструктор сообщение будет потеряно).  
В случае возможной генерации исключений-наследников и исключений-родителей и 
необходимости их по-разному обрабатывать, обработчик для исключения-наследника нужно 
располагать выше обработчика исключения-родителя. 
При необходимости можно определить свои исключения. Для унификации работы следует 
определять новые исключения как наследников std::exception или его наследников. У нового 
класса-исключения переопределяется метод what и по необходимости добавляется поле, в которое 
можно с помощью конструктора с параметром записать сообщение. 
4. 
Опасности исключений 
Вы могли заметить, что при генерации и обработке исключений нарушается «правильный» 
порядок действий, если в блоке try исполняются не все инструкции. Порой это весьма фатально: 
например, при работе с файлами и динамически выделенной памятью.

5. 
Идиома (концепция) RAII 
RAII (Resource Acquisition Is Initialization, получение ресурса есть инициализация) – подход, в 
соответствии с которым выделение памяти (получение ресурса) неразрывно связано с его 
инициализацией, а освобождение – с уничтожением самого объекта. Такой подход позволяет избежать 
в т.ч. проблем в случае досрочного завершения выполнения функций.  
6. 
Вложенные блоки обработки исключений 
Блоки обработки исключений поддерживают вложенность. Связка try-catch может быть 
вложена в блок try, а внутри catch могут генерироваться новые исключения. Вложенность может 
быть выражена явно, а также может проявляться в вызове внутри блоков функций, содержащих 
операторы работы с исключениями.  
Если исключение не должно быть обработано (до конца) в блоке catch на том же уровне, где 
оно было сгенерировано, его можно передать в вышестоящий блок вызовом throw без указания 
объекта. Этот способ является предпочтительным, т.к. при передаче словленной переменной или

7. 
Спецификация исключений 
Есть механизм спецификации исключений, который в большей части редко использовался на 
практике. Этот механизм позволяет указать, какие исключения может генерировать функция (и может 
ли вообще). Спецификация производится путём указания throw() в конце объявления функции. 
Есть 3 варианта спецификации (параметров throw):  
 исключения конкретного типа – параметром указывается тип или несколько типов; 
 исключения любого типа – параметром указывается многоточие; 
 никакие исключения – скобки остаются пустыми (единственный используемый случай). 
Со стандарта С++11 для запрета генерации исключений вместо throw() рекомендуется 
использовать спецификатор noexcept. В новых стандартах варианты со throw() уже исключены.

Стоит отметить, что спецификаторы запрещают функции бросать исключения (все или 
все, кроме разрешённых типов) наружу. Функции с запрещающими спецификаторами могут 
генерировать исключения и обрабатывать их внутри себя, не передавая наружу. 
+1 best practices: используйте noexcept для конструкторов копирования и перемещения, 
операторов присваивания и перемещения, деструкторов. Для корректной работы с ресурсами эти 
методы должны выполняться полностью и не должны прерываться. 
8. 
Функциональный блок try 
Для того, чтобы применять блок try ко всему телу функции, есть особый – т.н. 
«функциональный» вариант блока try. Он позволяет «прицепить» обработку исключения, 
генерируемого функцией, к самой функции. В примере 12 показано использование функционального 
try применительно к ситуации из примера 5. 
В отличие от примера 5, где строка с результатом не будет выведена на экран, в этом случае она 
выведется на экран, т.к. она находится вне блока try и выполняется в любом случае.
