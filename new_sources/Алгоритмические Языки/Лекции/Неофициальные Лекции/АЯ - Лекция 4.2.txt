Введение в CMake 
1. Что, зачем и для чего 
СMake – кроссплатформенная система автоматизации сборки, которая поддерживается 
большинством современных систем разработки (IDE).  
У многих IDE есть свои системы автоматизации сборки (например, Visual Studio, Qt Creator), но 
использование CMake избавит вас от зависимости от среды разработки. Для полноценной сборки 
проекта не всегда достаточно исходных файлов с кодом, в некоторых случаях критически важно 
использование конкретной версии стандарта, использование конкретных флагов для компилятора. Эта 
информация хранится в других файлах проекта, в формате, который требуется конкретной системе 
сборки. Использование одной и той же системы, поддерживаемой разными IDE, позволяет без проблем 
дома на Visual Studio дорабатывать код, который вы начали писать на ЛР в НОЦ ИБ в CLion. 
2. Как это использовать 
В CMake вся информация, необходимая для сборки, хранится в конфигурационном файле, 
который называется CMakeLists.txt. 
 Например, когда вы создаёте в CLion новый проект, в каталоге проекта создаётся файл с 
исходным кодом, файл CMakeLists.txt и каталог для отладочной (debug) сборки (build).

Итак, первая строка проверяет минимально необходимую для сборки проекта версию CMake. 
При создании проекта сюда вписывается версия CMake, используемая средой разработки. Строка 3 
задаёт название проекта, с которым связан текущий CMakeLists. Строка 5 определяет используемый 
стандарт С++ (в примере это 17 – С++17). Строка 7 определяет цель (target) – исполняемый файл или 
библиотека, который будет построен в результате сборки проекта. В данном случае цель – untitled5, 
которая собирается из main.cpp. Первым аргументом задаётся имя исполняемого файла, а далее через 
пробелы перечисляются файлы заголовков и файлы с исходным кодом, которые должны быть 
скомпилированы и слинкованы для получения исполняемого файла. 
При создании класса через IDE (рис. 2) по умолчанию добавляет класс в «цели». После 
добавления класса CMakeLists будет выглядеть как в примере 2.

Рис. 5. Выбор цели для построения решения. 
Вы, вероятно, заметили, что код в CMakeLists.txt – это не код на С++. Там используется свой 
язык с другим синтаксисом. В частности, комментарии в коде CMake должны начинаться с решётки 
(#). 
3. Что ещё можно делать в CMakeLists 
Вообще говоря, очень много всего. В нём есть логические операторы (NOT, AND, OR), 
условный оператор if() с ветвями else() и elseif() и завершающим оператором endif(), операторы 
сравнения (LESS, GREATER, EQUAL, LESS_EQUAL, MATCHES для использования регулярных 
выражений и т.д.), циклы while()-endwhile(), foreach()-endforeach() и даже функции и макросы. Вопрос 
в том, какую цель вы перед собой ставите.

4. Как работать с CMake в Visual Studio  
Если при установке VS вы не устанавливали компоненты из пункта «Разработка для Linux на 
С++»:  
1. Запустите программу «Visual Studio Installer» (можно найти через поиск на вашем 
компьютере)  
2. Около вашей версии VS выбираете «Дополнительно» -> «Изменить» (рис. 6).  
3. Находите там «Разработка для Linux на С++», проверяете, что стоит галочка напротив 
«средства CMake» и устанавливаете (рис. 7).
