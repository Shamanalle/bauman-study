# Теория: Умные указатели (Smart Pointers) в C++

До стандарта C++11 программистам приходилось вручную управлять динамической памятью через пару операторов `new` (для выделения) и `delete` (для освобождения). Это часто приводило к **утечкам памяти** (memory leaks), если программист забыл написать `delete`, или к падению программы, если память удалялась дважды или после исключения `throw` поток выполнения просто перепрыгивал строку с `delete`.

Для элегантного решения этой проблемы был придуман механизм RAII (Resource Acquisition Is Initialization), и на его основе построены "умные указатели".
Умный указатель — это класс, который оборачивает в себе обычный `raw` (сырой) указатель, выделяет память в конструкторе, а при уничтожении объекта (когда тот выходит из области видимости функции / блока `{ ... }`) **автоматически вызывает деструктор** и освобождает память.

В стандартной библиотеке `<memory>` есть два главных умных указателя: `std::unique_ptr` и `std::shared_ptr`. В этой работе мы написали их собственные аналоги: `MyUnique` и `MyShared`.

## 1. Уникальный указатель (`MyUnique`)

Концепция `unique_ptr` заключается в **строгом (уникальном) владении** ресурсом.
В один момент времени только ОДИН указатель класса `MyUnique` имеет право указывать на блок памяти в куче.

Именно поэтому у него **запрещены (удалены)** конструктор копирования и оператор присваивания с копированием:
```cpp
MyUnique(const MyUnique&) = delete;
```

Если нужно передать объект в другую переменную или вернуть из функции, используется **семантика перемещения** (`move`). Старый указатель отдает адрес памяти новому, а сам обнуляется:
```cpp
MyUnique<int> p1 = Make_MyUnique<int>(5);
MyUnique<int> p2 = move(p1); // Память перешла к p2, p1 == nullptr
```

## 2. Разделяемый указатель (`MyShared`)

Концепция `shared_ptr` заключается в **совместном владении** ресурсом.
Иногда нам нужно, чтобы один объект в памяти использовался в разных частях программы одновременно. 

Для этого внутри объекта `MyShared` хранится не только указатель на сами данные, но и указатель на **счетчик ссылок** (Reference Count) типа `size_t`.
- При создании счетчик равен 1.
- При **копировании** указателя (`MyShared p2 = p1`) счетчик увеличивается.
- При удалении (вызове деструктора) одной из копий, счетчик уменьшается.
- И **только когда счетчик станет равен 0** (удалилась последняя копия указателя, смотрящая на эту память), умный указатель вызывает `delete` для самих данных.

## 3. Variadic Templates и `Make_...` функции
Выделять память через глобальные функции (`make_unique` или в нашем случае `Make_MyUnique`) предпочтительнее и безопаснее, чем напрямую использовать `new` в коде (защита от утечек при последовательном выполнении аргументов функций компилятором).

Чтобы написать одну функцию-фабрику, которая способна конструировать объекты с **любым** числом аргументов, используются вариативные шаблоны (`template <typename... Args>`).
Мы упаковываем (пакуем) параметры всех типов в пакет `args`, а затем идеально их "распаковываем" и пробрасываем/передаем приложению дальше в конструктор целевого класса (`new T`) с помощью волшебной функции `forward<Args>(args)...`. Это самый мощный механизм шаблонного метапрограммирования в C++11.
