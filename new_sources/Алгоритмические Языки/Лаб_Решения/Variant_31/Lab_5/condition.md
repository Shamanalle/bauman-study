# Условие лабораторной работы №5 (Вариант 31)

## Тема: Использование ассоциативных контейнеров STL (`set`, `map`, `unordered_set`, `unordered_map`)

**Цель работы:**
Закрепить знания о работе со стандартной библиотекой шаблонов (STL), научиться использовать ассоциативные контейнеры в C++, основанные на сбалансированных деревьях поиска и на структурах хэш-таблиц. Понять, какие требования к классам предъявляют такие контейнеры.

## Общее задание:
1. Для выполнения данной работы необходимо модернизировать пользовательский класс, написанный в Лабораторной работе №4.
2. Прочитать данные из файла (как в прошлом задании) и добавить объекты в два ассоциативных контейнера, предназначенных для множеств:
   - **`std::set`** (упорядоченное множество, основанное на бинарном дереве, гарантирует логарифмическую сложность $O(\log n)$ поиска/вставки).
   - **`std::unordered_set`** (неупорядоченное множество, основанное на хэш-таблице (bucket collection), гарантирует константную сложность $O(1)$ при отсутствии коллизий).
3. Чтобы объекты пользовательского класса могли быть вставлены в упорядоченный контейнер (дерево) `std::set`, необходимо:
   - Подготовить функцию-компаратор, либо **перегрузить оператор связывания (отношения) «<» (меньше)**.
   - *Важно: если сортировать только по одному параметру, объекты с одинаковым параметром будут считаться математически эквивалентными, и дубликат (по мнению дерева) не добавится во множество. Следует предусмотреть составное условие.*
4. Чтобы объекты могли быть вставлены в хэш-таблицу `std::unordered_set`, необходимо:
   - Подготовить функцию (перегрузить оператор) для проверки объектов на точное **эквивалентность (равенство) «==»**.
   - Написать **функцию хэширования**. Как правило, для этого программист явно специализирует системный шаблон структуры `std::hash<Type>`. Функция должна возвращать тип данных `size_t` и использовать логические битовые комбинации (XOR) для генерации хэша на основе полей объекта.
5. Напечатать состав каждого контейнера (содержимое дерева должно автоматически вывестись отсортированным, а содержимое хэш-таблицы — в произвольном, зависящем от хэшей порядке).
