# Теория: Наследование и Полиморфизм в C++

В данной лабораторной работе изучаются два ключевых принципа ООП: наследование и полиморфизм.

## 1. Наследование
Наследование позволяет создать новый класс (наследник / производный) на основе уже существующего (базового родителя). Класс-наследник получает (наследует) все поля и методы базового класса и может добавлять свои собственные.

```cpp
class RealNumber { ... };
class ComplexNumber : public RealNumber { ... }; 
```
Слово `public` перед названием родителя означает "публичное наследование". Это означает, что `public` члены родителя остаются `public` в наследнике, а `protected` остаются `protected`.

### Модификатор `protected`
В ЛР1 мы использовали `private` для сокрытия полей. Но `private` поля недоступны даже классам-наследникам. Чтобы поле нельзя было изменить извне (`main`), но можно было использовать внутри наследников, применяется спецификатор `protected`. Именно поэтому поля базового класса объявляются как `protected`.

### Вызов конструктора родителя
Конструктор наследника **обязан** инициализировать часть объекта, которая досталась ему от базового класса. Делается это в списке инициализации:
```cpp
ComplexNumber(double real, double imag) : RealNumber(real) {
    imaginary = imag;
}
```

## 2. Полиморфизм
Полиморфизм — это свойство системы использовать объекты с одинаковым интерфейсом без информации о типе и внутренней структуре объекта (возможность "функции работать по-разному" для разных объектов).

### Статический полиморфизм (Статическое связывание)
Связывание вызова функции с её телом происходит на этапе **компиляции** (раннее связывание).
Примеры:
1. Перегрузка функций (две функции с одним именем, но разными типами аргументов).
2. Вызов обычного не-виртуального метода через указатель базового типа:
   ```cpp
   Base* ptr = &derivedObj;
   ptr->Base::method(); // Всегда вызовет метод базового класса
   ```

### Динамический полиморфизм (Динамическое связывание)
Связывание происходит на этапе **выполнения** (позднее связывание).
Достигается за счет использования ключевого слова `virtual` перед методом в базовом классе.

Как это работает:
1. Когда компилятор видит модификатор `virtual`, он создает специальную невидимую **таблицу виртуальных функций (vtable)** для этого класса.
2. В объект незаметно добавляется указатель на эту таблицу (`vptr`).
3. При вызове виртуального метода через родительский указатель (`ptr->print()`), программа сначала идет по указателю `vptr` в таблицу и находит **правильный** адрес функции, который соответствует *реальному* типу объекта, лежащему в памяти.

```cpp
Base* ptr = &derivedObj; // Указатель базовый, но объект наследника
ptr->print(); // Вызовет Derived::print(), а не базовую функцию!
```
Это самая мощная архитектурная особенность С++, позволяющая писать универсальный код для обработки разных типов данных через их общий базовый интерфейс.
