# Условие лабораторной работы №8 (Вариант 35)

## Тема: Умные указатели (Smart Pointers)

**Цель работы:**
Вникнуть в устройство механизмов автоматического управления памятью (RAII). Самостоятельно реализовать аналоги стандартных умных указателей `std::unique_ptr` и `std::shared_ptr`, а также освоить шаблоны с переменным числом аргументов (Variadic Templates).

## Индивидуальное задание (Общее для всех вариантов):
Разработать два шаблона пользовательских умных указателей, которые обеспечивают автоматическое удаление выделенной динамической памяти при выходе из области видимости, исключая необходимость вручную вызывать `delete`:

1. **`MyUnique`** (Уникальный указатель):
   - Указатель владеет объектом единолично (монопольно).
   - В любой момент времени памятью управляет только один экземпляр `MyUnique`.
   - **Конструктор копирования и копирующее присваивание должны быть запрещены** (`= delete`), чтобы исключить случайное "размножение" владельцев указателя.
   - **Конструктор перемещения и перемещающее присваивание должны быть разрешены**, чтобы можно было передавать права владения на объект (с помощью `std::move`).

2. **`MyShared`** (Разделяемый указатель):
   - Указатель владеет объектом совместно с другими такими же указателями.
   - Реализуется через подсчет ссылок (Reference Counting).
   - **Конструктор копирования и копирующее присваивание разрешены.** При копировании счетчик ссылок увеличивается на 1.
   - Деструктор уменьшает счетчик на 1. Выделенная под объект память очищается оператором `delete` **только** в том случае, когда счетчик опускается до нуля (и ни один указатель больше не смотрит в этот адрес).

3. **Функции генераторы (фабрики):**
   - Написать глобальные шаблонные функции `Make_MyUnique` и `Make_MyShared` (аналоги `std::make_unique` и `std::make_shared`).
   - Для того, чтобы эти функции могли обрабатывать произвольное количество параметров (и передавать их в конструктор упаковываемого объекта), необходимо использовать **шаблоны с переменным числом аргументов** (Variadic Templates: `typename... Args`).
   - Внутри фабрики нужно использовать механизм **идеальной передачи** (`std::forward`), чтобы сохранить характеристики типов аргументов при их передаче в конструктор (`new T(forward<Args>(args)...)`).

4. **Тестирование:**
   - Написать любой пользовательский класс с конструктором и деструктором (в которых есть `cout`, чтобы можно было отследить момент создания и уничтожения объекта) и продемонстрировать на нём работу обоих умных указателей в `main`.
