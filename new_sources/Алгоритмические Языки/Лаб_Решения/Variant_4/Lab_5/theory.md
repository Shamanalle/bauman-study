# Теория: Ассоциативные контейнеры в C++ (`set` и `unordered_set`)

В отличие от последовательных контейнеров (`std::vector`), где элементы хранятся в порядке их добавления, **ассоциативные контейнеры** сами управляют расположением данных для того, чтобы максимально ускорить их поиск (за счет древовидных или хэш-структур). 

Оба контейнера (`std::set` и `std::unordered_set`) хранят только **уникальные** элементы. Если попытаться добавить элемент, который там уже есть, он не добавится повторно.

## 1. Контейнер `std::set`

`std::set` — это множество. Под капотом оно реализовано на основе сбалансированного бинарного дерева поиска (обычно это Красно-чёрное дерево Red-Black Tree).
- **Сложность поиска/вставки:** $O(\log n)$ (логарифмическое время).
- **Порядок обхода:** Гарантируется, что при обходе контейнера циклом `for (auto& item : set)` элементы будут выдаваться в **строго отсортированном виде** (от меньшего к большему).

### Требования к классу
Чтобы дерево "понимало", какой элемент меньше, а какой больше (кто должен идти "левее", а кто "правее" в узлах дерева), мы обязаны перегрузить **оператор `<` (меньше)**.

*Важно:* Если перегрузить только сравнение по одному полю, то два разных объекта с одинаковым значением этого поля будут восприняты как *один и тот же* объект (так как `!(a<b)` и `!(b<a)` означает в дереве эквивалентность `a==b`), и второй будет удален. Поэтому обязательно добавляется дополнительный критерий сравнения.

## 2. Контейнер `std::unordered_set`

`std::unordered_set` — это хэш-множество (или корзина без порядка). Под капотом реализовано на основе хэш-таблицы (Hash Table).
- **Сложность поиска/вставки:** $O(1)$ в среднем (мгновенно), $O(n)$ в худшем случае при коллизиях.
- **Порядок обхода:** Элементы лежат хаотично случайным образом, в зависимости от вычисленных хэшей. Никакого порядка нет.

### Требования к классу
Для хранения в хэш-таблице дереву не интересно, кто больше или меньше. Ему важны 2 вещи:
1. **Функция сравнения на равенство** (оператор `==`): нужна для проверки двух объектов на совпадение при коллизиях хэшей.
2. **Как вычислять хэш-код** объекта (целое число, по которому таблица определяет номер "корзины"):
   Для стандартных типов `std::hash` уже написан. Для нашего собственного класса программист должен реализовать алгоритм хэширования, написав специализацию внутри пространства имен `std`:
   ```cpp
   namespace std {
       template<>
       struct hash<MyClass> {
           size_t operator()(const MyClass& obj) const {
               // Логика математического перемешивания полей
           }
       };
   }
   ```
