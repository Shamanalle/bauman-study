# Теория: Многопоточность (Multithreading) в C++11

До стандарта C++11 многопоточность в C++ реализовалась через платформозависимые библиотеки (POSIX threads для Linux, Windows API Threads для Windows). Начиная с C++11 в стандартную библиотеку вошел мощный механизм для работы с потоками.

## 1. Что такое поток (Thread)
Поток — это наименьшая независимая единица выполнения кода. В многопоточном приложении (в отличие от однопоточного) главный поток может породить несколько "дочерних" потоков, которые будут работать (выполнять свои функции) **параллельно** (одновременно на разных ядрах процессора или псевдо-одновременно на одном).

## 2. Гонка данных (Data Race) и Синхронизация (`std::mutex`)
Поскольку все потоки находятся внутри одной программы, они имеют доступ к **общей памяти**. Если несколько потоков одновременно попытаются вывести текст в консоль (`std::cout`) без синхронизации, их вывод может смешаться (буквы первого потока переплетутся с буквами второго).

Для решения этой проблемы используется **Мьютекс** (от *mutual exclusion* — взаимное исключение), реализованный классом `std::mutex`.
Мьютекс подобен ключу от комнаты:
1. Поток подходит к комнате (`cout`) и пытается захватить мьютекс (`lock`).
2. Если ключ свободен, он берет его, заходит в комнату, печатает, а потом отдает ключ (`unlock`).
3. Если второй поток подходит к комнате, пока там первый, он видит, что ключа нет, и **ждет** (блокируется), пока первый не выйдет.

В С++ хорошим тоном является использование `std::lock_guard`. Это обертка над мьютексом, которая захватывает его в конструкторе и **автоматически** освобождает в деструкторе, когда функция завершает работу (даже если в функции произойдет `throw`). Это RAII-подход (Resource Acquisition Is Initialization).
```cpp
void safePrint(...) {
    std::lock_guard<std::mutex> lock(cout_mtx); // Автоматический lock
    cout << ... ;
    // Автоматический unlock при выходе из функции
}
```

## 3. Разница между `std::thread` и `std::async`

### `std::thread`
- Это низкоуровневый системный поток.
- Как только вы пишите `std::thread t(func)`, поток "железно" создается операционной системой и сразу начинает работу.
- Вы **обязаны** вызвать метод `join()` (ожидание завершения) или `detach()` (отсоединение), иначе программа аварийно упадет при вызове деструктора у объекта `t`.
- `std::thread` не умеет возвращать значения (кроме как через параметры по ссылке или глобальные переменные).

### `std::async` и `std::future`
- Это более высокоуровневый механизм, абстракция над потоками (называется "Асинхронные задачи" / Task-based concurrency).
- Вы вызываете `std::async(func)`, а он возвращает объект `std::future`.
- `std::future` — это "обещание", что в будущем в этом объекте появится результат работы функции.
- Если функция отработала (или мы хотим ее дождаться), мы вызываем метод `get()` у объекта `future`. Если задача еще не выполнена, главный поток "заснет" и подождет её.
- Ключевое отличие: `async` умеет **возвращать** значение из потока. Если функция возвращает `int`, то `future<int>::get()` вернет этот `int`.
- `async` может сам решать, создавать новый системный поток или выполнить задачу в текущем потоке (зависит от флага `std::launch::async` или `std::launch::deferred`).
